## 1. 交付物与制度

| 交付物 | 说明 |
|---|---|
| `database/migrations/V0001__M00_03_migration_policy_baseline.sql` | 唯一生产 SQL 源码入口；无业务表的 checksum 策略标记迁移。M01+ 从 V0002 写入各自拥有的表。 |
| `src/test/resources/m003-fixtures/V900001__M00_03_transaction_example_fixture.sql` | 仅测试 classpath 使用的 InnoDB 事务/outbox stub；不会进入生产 JAR，也不得被业务域复用。 |
| `campus-common` Flyway 依赖与 resources 配置 | 由 Spring Boot 3.5.15 BOM 锁定 Flyway `11.7.2`，构建时把 SQL 复制为 `classpath:db/migration`；JAR 内已检查到该路径，不依赖启动 cwd。 |
| `CampusFlywayMigrationConfiguration` | checksum、历史缺失和执行失败统一以 `MIGRATION_BLOCKED` 阻断启动；不启用 silent baseline。 |
| `MigrationPlan` | 发布记录所需的 `fromVersion/toVersion/backupPrerequisite` 契约。 |
| `TransactionPolicy`、`TransactionExecutor`、`CampusTransactionConfiguration` | REQUIRED 事务、有界 1–3 次完整事务重试；逐项白名单 MySQL 1213/1205；乐观锁不重试，耗尽为 `RETRYABLE_CONFLICT`；Spring Bean 名为 `campusTransactionExecutor`。 |
| `docs/transactions.md` | 增量制度、生产备份前置、锁顺序、传播规则、重试边界与外部副作用禁令。 |

应用配置固定：`spring.flyway.validate-on-migrate=true`、`clean-disabled=true`、
`baseline-on-migrate=false`、`out-of-order=false`、`spring.sql.init.mode=never`；Flowable
`database-schema-update=false`。生产/开发均不允许 ORM 或工作流启动时自动建表/改表，只有 Flyway 增量 SQL
可创建自有结构。

## 3. 自动化结果

```powershell
# 事务策略和既有 campus-common 用例
cd backend
. ..\scripts\dev-env.ps1
mvn -B -pl campus-common clean test -DskipITs
# Tests run: 74, Failures: 0, Errors: 0, Skipped: 0 — BUILD SUCCESS

# 隔离 MySQL 8.4 迁移用例（环境变量指向 disposable schema）
mvn -B -pl campus-common -Dtest=M003MySqlMigrationIT test
# Tests run: 4, Failures: 0, Errors: 0, Skipped: 0 — BUILD SUCCESS

# 包含发布 JAR 的构建
mvn -B -pl campus-common,yudao-server -am package -DskipTests
# 23/23 reactor modules — BUILD SUCCESS
```

真实 MySQL 用例逐项断言：

1. 从空 schema 迁移至生产 `v0001` 加测试 fixture `v900001`，存在两个 fixture 示例表和两条成功历史记录；再次运行 `migrationsExecuted=0`。生产 JAR 仅含 V0001，不含 fixture。
2. 将已经执行的临时迁移副本追加注释后 `flyway.validate()` 抛出 `FlywayValidateException`，证明 checksum 阻断。
3. 注入“第二次写入后抛错”：示例聚合表和 outbox stub 均为 0 行，证明同一 REQUIRED 事务回滚。
4. 注入一次 `CannotAcquireLockException` 后重跑完整事务，第二次写入成功且仅一行；单元用例另断言乐观锁不重试、耗尽产生 `RETRYABLE_CONFLICT`。
5. `SQLTransactionRollbackException` 的 1213/1205 分别按 policy 白名单判断：仅允许 deadlock 时 1205 不重试，
   仅允许 lock timeout 时 1213 不重试；另验证 `campusTransactionExecutor` 可由 Spring 标准注入。

打包检查已确认 `campus-common-2026.08-campus.1.jar` 仅含
`db/migration/V0001__M00_03_migration_policy_baseline.sql`，而 `yudao-server.jar` 含 campus-common 与 Flyway core/MySQL
嵌套依赖。

## 4. 历史库防护验证

在同一个一次性 MySQL 中先导入上游 `ruoyi-vue-pro.sql` 和 `quartz.sql`（59 张上游表）、不创建 Flyway
历史，再从 `backend` 工作目录启动已打包的 `yudao-server.jar`。Flyway 在读取 JAR classpath 中的迁移后发现
非空 schema 且历史缺失，应用以如下稳定语义停止：

```text
MIGRATION_BLOCKED: inspect schema history and apply a reviewed forward repair; do not edit applied SQL
Caused by: Found non-empty schema(s) `campus_m003` but no schema history table.
```

这验证了“缺历史版本阻断、不能自动 baseline”的生产保护。该验证故意未让服务完整启动；它不是启动失败缺陷。

## 5. 事务约定摘要

- 业务应用服务默认 `@Transactional(REQUIRED)`；跨域同步命令加入调用方事务，禁止意外 `REQUIRES_NEW`。
- 锁顺序：资金控制/冻结 → 身份资格/库存/名额 → 订单/任务聚合 → 附属记录和本地 outbox。
- 自动重试只可用于已有唯一键/幂等键且无外部副作用的 MySQL 锁冲突；网关调用经 M00.05 outbox，在提交后执行。
- DDL 不依赖回滚。破坏性变更要经过扩展、双版本兼容、切换和后续清理，并有备份/前向修复计划。

## 6. 未验证与风险

1. Flyway `11.7.2` 在真实 MySQL 8.4.11 上完成所有验收，但运行时给出“8.4 比该 Flyway 已测试的 8.1 更新”的升级提示；发布前应升级/复验一个官方声明支持 MySQL 8.4 的锁定 Flyway 版本，不能忽略该提示。
2. 当前为第一个自有迁移，尚无“上一正式自有版本”可升级；空 schema（V0）→ V0001 已验证。既有 59 上游表库的人工、显式 baseline V0 接管流程在 `database/README.md`，后续每个发布都要在前一 release 的 fixture/schema 上跑升级与双版本兼容演练。
3. B 级尚未验证真实业务跨域表、M00.04 幂等键和 M00.05 正式 `campus_outbox` 的同事务写入；本模块只证明最小 stub 机制。
4. C 级预发备份恢复、失败 DDL 的人工前向修复演练和生产发布恢复尚未执行。
