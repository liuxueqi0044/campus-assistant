# M00.04 持久化幂等命令验收

## 已交付

`campus-common/idempotency` 提供 `IdempotentCommandExecutor`、`RequestCanonicalizer`、
`IdempotencyRepository` 及命令上下文/结果类型。执行器用 REQUIRED 事务完成占位、业务回调和结果落库；
异常会回滚占位。相同键的并发请求通过 MySQL `INSERT ... ON DUPLICATE KEY UPDATE` + `SELECT FOR UPDATE`
等待胜者，不在唯一键异常后的 rollback-only 事务中查询。

请求体使用递归排序字段后的 JSON 计算 SHA-256，且递归排除精确名称为 `traceId` 的传输元数据字段；客户端幂等键只保存摘要，不写日志或表。相同摘要的完成记录
会在重新授权后返回 `replayed=true` 的同义结果，异体映射 `CAMPUS_IDEMPOTENCY_CONFLICT`，已提交处理中记录
映射 `CAMPUS_COMMAND_IN_PROGRESS`。

## 验证命令

在 `backend` 目录执行：

```powershell
mvn -B -pl campus-common -am test -DskipITs
```

可选真实 MySQL 验收（未配置变量时 JUnit 自动跳过）使用：

```powershell
$env:CAMPUS_MYSQL_IT_URL = 'jdbc:mysql://127.0.0.1:3306/campus_it'
$env:CAMPUS_MYSQL_IT_USERNAME = 'campus_it'
$env:CAMPUS_MYSQL_IT_PASSWORD = '***'
mvn -B -pl campus-common -am -Dtest=M004MySqlIdempotencyIT test
```

也兼容仓库现有的模块变量 `CAMPUS_M004_MYSQL_*` 和 M00.03 的 `CAMPUS_M003_MYSQL_*`。
`M004MySqlIdempotencyIT` 使用真实 MySQL 迁移 V0001–V0003，并验证 50 个并发同键请求、同键异体冲突、
业务失败回滚后重试。未配置连接变量时只能报告 `SKIPPED/EXTERNAL_NOT_READY`，不能写成 A 级通过。

2026-09-17 的 [GitHub Actions M00.04 A 验收](https://github.com/liuxueqi0044/campus-assistant/actions/runs/35208055825)
在隔离 MySQL 8.4.11 上通过：三个显式选择的测试类均生成报告且无跳过；随后删除
`uk_campus_idempotency_identity`，50 并发用例按预期失败，证明并发正确性确实依赖数据库不变量而非偶然串行。
报告以构建产物 `m00-04-a-report` 归档。因此 M00.04 当前为 `A 通过`。

## 接入约束

业务 handler 不得在回调内调用 HTTP、支付、短信或其他外部网关；此类效果应在同一事务写入 M00.05
outbox/任务表。业务表和事件表仍由业务模块与 M00.05 分别保证唯一性。
