- `campus-test-support`：只供测试使用的独立 jar，提供 `CampusFixtureFactory`、`MutableClock`、

  的脱敏固定数据唯一来源。
- `scripts/ci/m00_acceptance.py` 与 `m01_acceptance.py`：显式选择 M00.04、M00.05、M01.01 A 级用例，
  输出源码 SHA、迁移、依赖、用例计数、`PASS/FAIL/EXTERNAL_NOT_READY` 和未验证项；跳过、零用例、
  异常退出均不能变成成功。
- `check_acceptance_reports.py`：在报告归档后统一校验三个模块、真实 MySQL 标志、所有必需测试及
  M00.04 变异门禁，避免前序失败被后续上传步骤掩盖。
- M00.04 变异门禁：在测试 JVM 内显式删除 `uk_campus_idempotency_identity`，并发用例必须失败；
  如果变异运行未执行用例、被跳过或意外成功，验收入口自身失败。
- `.github/workflows/ci.yml`：契约、验收入口自测、测试数据扫描、共用隔离 MySQL 的三个 A 级验收、后端测试与
  完整打包、前端检查、依赖清单和 Gitleaks 门禁；第三方 Actions 与 MySQL 镜像固定到审查过的提交或摘要。

## 外部条件与状态语义

本机 Docker/MySQL 当前不可用。未提供 MySQL 时，三个入口已验证会生成 `EXTERNAL_NOT_READY` 报告并以
非零码退出；这不是 A 级通过证据。GitHub Actions 使用隔离的 MySQL 8.4.11 服务执行正常并发用例和
唯一约束破坏用例，任何跳过、缺失报告或未捕获异常都会阻断任务。

B 级需要把版本化 stub 替换为真实相邻模块并验证跨校拒绝和零副作用；C 级微信、支付证据必须单独归档，
缺少渠道或商户权限时继续保持 `EXTERNAL_NOT_READY`。M00.06 工具不能替代这些模块自身的 B/C 验收。

## 重跑与清理

- CI MySQL service 每个任务独立创建并随任务销毁；本地执行只能连接专用空测试库。
- `artifacts/` 是本地生成目录，不提交仓库；GitHub Actions 将验收、扫描及依赖清单作为构建产物保存。
- 固定样本编号语义不可原地改变；需要变更时新增版本，并保留旧版本兼容窗口。
