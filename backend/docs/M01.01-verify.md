## 固定契约

- 学生端调用 `POST /app-api/campus/v1/auth/wechat/login`，请求只有 `code` 与可选 `clientContext`。
- 响应为校园 `code/message/data/traceId` 信封；`data` 包含 `accessToken`、`expiresAt`、`userId`、`profileCompletion`，不含 refreshToken、openid、session_key 或渠道 token。
- 登录与退出分别为精确的匿名放行项；签发的 OAuth2 userType 固定为 `MEMBER`，不能作为管理端 Token。
- 学生端调用 `POST /app-api/campus/v1/auth/logout`。它从 Bearer token 提取会话，并在固定平台租户内委托上游 member `logout` 完成撤销与审计；缺失或已撤销 token 仍幂等返回 `data: true`。学生端当前没有使用 refreshToken，校园登录响应不暴露它。

## 数据与事务

- `V0004__M01_01_wechat_identity.sql` 创建全局表 `campus_wechat_identity_binding`，以 `(app_id, open_id)` 与非空的 `(app_id, union_id)` 作数据库唯一约束。
- code 交换先执行，不包在数据库事务或平台租户边界中；后续绑定、会员创建、状态检查、Token 签发与退出撤销都固定在服务端 `campus.platform-tenant-id`（默认 `1`）内，外部 tenant header 不能改变它。
- 会员创建与绑定插入在 `WechatIdentityBindingService` 的同一事务内。并发唯一冲突使失败事务回滚其新建 member，随后在事务外回读 openId 赢家；若 UnionID 指向另一 openId，返回冲突而不泄漏数据库异常。只有事务成功后才签发 Token。
- unionId 仅取可信渠道返回；遇到已关联不同 openId 时返回 `IDENTITY_BINDING_CONFLICT` 并进入人工处理，绝不自动合并账号。

## 运行前配置与真实验证

服务端使用现有 `wx.miniapp.appid`/`wx.miniapp.secret` 配置（生产环境由
`CAMPUS_WECHAT_MINIAPP_APP_ID` 与 `CAMPUS_WECHAT_MINIAPP_SECRET` 提供）。请使用与小程序匹配的真实凭证，且不要把凭证、code 或 Token 写入日志、截图或 issue。
微信 code 交换默认连接超时 3 秒、读取超时 5 秒，可分别用 `campus.wechat.connect-timeout` 与
`campus.wechat.read-timeout` 调整；任何网络超时都映射为 `IDENTITY_PROVIDER_UNAVAILABLE`，且不会记录 URL 查询参数。

真实小程序 C 级验证尚需在受控环境执行：首次登录、再次登录、禁用 member、退出旧会话、微信渠道故障重试，并检查普通应用日志与绑定表均不含 code/session_key/完整 token。
