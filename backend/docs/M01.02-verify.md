## 1. 交付边界

- 新模块 `campus-module-identity` 提供 `GET /app-api/campus/v1/schools`、`GET /context`、`PUT /context` 与 `CampusScopeApi`。
- `campus_school`、`campus_campus`、`campus_user_browse_preference` 是 V0002/M01.02 负责的表；没有创建、读取或修改 `campus_membership`。
- 请求没有 tenant/header 数据范围；范围只从已验证 school/campus 行计算。公开 DTO 不含 membership、认证、角色、运营联系人或个人资料。
- 所有公开 ID 是 JSON 字符串：学校字段为 `schoolId`；校区字段为 `schoolId` 和 `campusId`。context 顶层 `loggedIn` 是显示语义，不能推导 membership。
- 迁移以 `(school_id, campus_id)` 复合外键保证 preference 归属，以 `user_id` 唯一键保证一人一行；应用层额外校验学校和校区启用。匿名 PUT 不调用 preference upsert。
- `V900002__M01_02_public_directory_fixture.sql` 仅在测试 classpath 中；生产 V0002 无 INSERT，生产 `campus-common` JAR 仅含 V0001/V0002。

## 3. 公开接口与错误

| 路径 | 匿名行为 | 登录行为 |
| --- | --- | --- |
| `GET /schools` | 返回启用目录 | 同匿名，绝不扩大私有范围 |
| `GET /context` | `loggedIn=false`、仅 `PUBLIC` 浏览语义 | 可读取独立浏览偏好；不输出 membership/role |
| `PUT /context` | 校验后回显，零落库 | 校验后 UPSERT 独立 browse preference |

- `CAMPUS_SCHOOL_MISMATCH`：`1040001000` / 400 / `USER_FIX`
- `CAMPUS_UNAVAILABLE`：`1040001001` / 409 / `USER_FIX`

### 安全接线故障与修复

首轮真实 `yudao-server` 验收曾发现三个 canonical 路径全部被认证兜底为 401，且 preference 表保持 0 行。根因不是业务层落库逻辑：`CampusContextController` 位于 `controller.app` 包，Yudao MVC 会自动附加 `/app-api`；原 Controller 又在 `@RequestMapping` 中写入完整 `/app-api/campus/v1`，造成最终 MVC 路由和注解扫描注册为双前缀 `/app-api/app-api/campus/v1/...`，canonical 路径未命中。

修复将 Controller 映射改为模块相对的 `/campus/v1`，并用上游成熟扩展点 `AuthorizeRequestsCustomizer` 明确注册三条、且仅三条规则：`GET /app-api/campus/v1/schools`、`GET /app-api/campus/v1/context`、`PUT /app-api/campus/v1/context`。不使用 `/**`，不会放行其他 campus/admin/system URL。`CampusIdentitySecurityFilterChainTest` 以真实 Spring Security FilterChain 回归这些规则；Controller 测试同时固定其相对映射，防止双前缀回归。

修复后的完整 `yudao-server` 已在隔离 MySQL/Valkey 中复验。复验额外发现上游租户过滤器仍会拦截匿名请求；最终通过框架既有 `@TenantIgnore` 扩展点，让这三个公开校园范围接口同时绕过 SaaS 租户上下文（仍保留精确的 Spring Security 放行规则）。真实 HTTP 结果：目录与 context GET/有效 PUT 为 200，错配 PUT 为 400，停用校区 PUT 为 409，未声明的 campus 路径仍为 401；匿名 PUT 后 `campus_user_browse_preference` 保持 0 行。

## 4. 风险与实现约束

- `CampusScopeApi` 只校验公开 school/campus 归属与启用性，不替代 M01.03 membership 或 M01.04/M01.06 资源授权。
- 重复 PUT 通过 MySQL `ON DUPLICATE KEY UPDATE` 收敛为一个 user 行；停用后不自动迁移到其他校区。
- Flyway 提示 MySQL 8.4 高于已测试版本，沿用 M00.03 的发布前升级/复验风险。
