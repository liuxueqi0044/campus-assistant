# ADR-0001：上游工程基线

- 状态：Accepted for implementation
- 日期：2026-09-17
- 对应任务：M00.01

## 背景

项目需要复用成熟账号、权限、文件和支付基础设施，同时保持校园业务的独立领域边界。架构基线选择芋道后端及其配套管理端、unibest 和 Wot UI。当前实施约束要求先完成非 UI 工程，前端 UI 留给其他执行方。

## 决策

1. 后端从 `YunaiV/ruoyi-vue-pro` 的 `master-jdk17` 分支导入精确提交 `8e43004cf68a405cd3485f98f8a539b97ca6544a`。
2. Java 基线保持 17；Spring、Maven 和上游依赖版本先沿用固定提交，不在导入时批量升级。
3. 首期保留框架、system、infra 和 server；member、pay 按后续领域需要受控启用。ERP、CRM、商城、工作流和通用 AI 模块不得成为最小运行路径的依赖。
4. 上游源码进入 `backend/`，不保留嵌套 Git 元数据。本地补丁必须记录，不对上游类进行无意义重命名。
5. 学生端和管理端只记录官方来源与候选提交，不在 M00.01 中实现或改造 UI；接手 UI 的执行方必须重新确认锁文件、构建链和真机基线。
6. 本地数据库固定 MySQL 8.4 系列；当前开发镜像固定为 `mysql:8.4.11` 的多架构摘要。缓存固定为 Valkey 8.1.10；其 Redisson、Lua、过期和锁行为已经通过本机兼容测试。

## 后果

- 优点：上游来源可追溯，校园业务可以集中在自有模块，后续升级差异可审查。
- 成本：上游当前版本名含 SNAPSHOT，必须依靠精确源码提交和实际解析后的依赖清单保证复现。
- 验证结果：便携式 Java 17 与 Maven 校验通过；24 个后端模块构建通过；Docker daemon 已恢复，MySQL 与 Valkey 容器健康；Valkey 的 Redisson/Lua/TTL/锁兼容测试与 prod readiness 已通过。
- 外部限制：微信真机、真实商户支付和公网回调仍需正式凭据与部署环境，不属于本地基线通过项。

## 验收门槛

- 后端来源、提交、许可证和本地补丁记录完整。
- XML/POM 静态结构可解析，且没有嵌套 `.git`。
- 安装或提供隔离的 Java 17 与 Maven 后，在两个干净目录构建并比较依赖解析和产物摘要。
- 生产 profile 启用模拟支付时必须启动失败；该保护已落码并由单元测试和真实进程验证。
