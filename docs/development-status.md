# 校园助手实际开发状态

更新时间：2026-09-17（Asia/Shanghai）

本页记录仓库中经过复核的实际状态。产品方案、模块设计和 `任务索引.json` 仍用于描述目标与依赖，
但不能替代代码、自动化测试和真实进程证据；状态变更必须链接到对应模块的验收记录。

## 状态口径

- `A 通过`：模块边界内的代码、契约和自动化验收完成。
- `B 联调通过`：前后端或跨模块真实调用通过，且失败语义经过验证。
- `C 环境通过`：预发/真机/真实第三方或恢复演练通过。
- `进行中`：已有明确所有权和验收标准，尚未通过对应等级。
- `未开始`：只有设计，不能因页面 demo 或 stub 存在而记为实现。

## 当前集成顺序

1. 执行 M01.02 前后端真实 context 联调，并将 M01.01 接到真实 member/OAuth2 持久化取得 B 级证据。
2. 使用受控测试小程序完成 M01.01 真实微信 code2session、禁用账号、退出撤销与渠道故障验收。
3. 在进入订单、支付等高副作用域前，把 M00.05 接入首个真实业务消费者，并验证 M00.04 与 outbox 的同事务边界。
4. 后续每个小模块由独立执行任务实现；架构负责人按表归属、接口不变量、权限边界、迁移可逆性和测试证据验收。

## 已知工程风险

- 前端交付代码已并入本仓库的 `frontend/`，后续应保持前后端契约变更同步评审。
- Flyway 11.7.2 已在 MySQL 8.4.11 实测通过，但运行时声明官方测试上限为 MySQL 8.1；升级前必须复跑迁移验收。
- 完整新库不能只对空 schema 启动应用；必须先导入固定 SHA 的上游基线，再按 `database/README.md` 人工显式 baseline V0。
- 前端 demo 模式可运行不代表真实业务后端已经实现；B 级状态只由真实 API 联调证据产生。
