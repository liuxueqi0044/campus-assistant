# 校园助手：产品功能与手机端视觉方案 v0.1

用途：供创始人、校内伙伴与设计开发共同评审。当前是建议基线，尚未完成真实用户测试。产品名称暂用“校园助手”；界面中的学校、人物、商品和订单均为演示内容。

## 1. 产品定位

面向大学生的手机端校园生活助手，将课表、同校区二手交易、跑腿和活动放在一个入口。用户能够快速找到信息、联系对方、完成事务，并清楚看到进展。

采用一个独立品牌、一套平台、多学校与校区配置。以当前校区作为二手、跑腿和活动的默认范围；课表属于个人。学生身份与学校官方背书分别展示，不混淆。

先提供适合微信分享和手机使用的体验，首发载体建议微信小程序。具体开发框架在评审实现方案时确定。本文件不承诺原生系统小组件、后台提醒或全国教务自动导入能力。

## 2. 导航与信息结构

底部固定四个入口，所有入口同时显示线性图标和文字：

| 入口 | 一级内容 | 主要行为 |
| --- | --- | --- |
| 校园 | 校区、搜索、下一节课摘要、二手 / 跑腿 / 活动切换 | 浏览、筛选、发布、查看详情 |
| 课表 | 今日 / 周课表、学期与周次、导入和编辑 | 看课、改课、检查导入结果 |
| 消息 | 服务通知、交易会话、跑腿会话、活动通知 | 回复、查看订单、处理待办 |
| 我 | 个人资料、认证状态、我的发布、我的订单、活动与设置 | 管理个人事务、寻求帮助 |

“校园”内部保留二手、跑腿、活动的位置，不因为某校区未开放就移动导航。未开放时解释当前状态，禁止展示可下单的假入口。

普通用户打开后默认进入校园，恢复上次浏览的服务分类。课表使用者可以在设置中选择默认打开课表。切换底部入口时保留各页面浏览位置和未提交草稿。

## 3. 学生端功能

### 3.1 通用基础

- 浏览允许先选择学校和校区；发帖、联系、下单等操作再触发登录。
- 个人资料：昵称、头像、学校、校区；认证状态明确区分未认证、审核中、已认证。
- 认证方式按校区配置，收集完成核验所需的最少信息；审核材料不公开展示，保存和删除规则明确。
- 校园搜索按二手、跑腿、活动分别返回结果，支持清空、空结果和重新筛选。
- 收藏、分享、举报、屏蔽、通知设置、客服入口。
- 发布草稿、图片上传进度、失败重试、内容编辑、下架与删除。
- 用户资料页仅显示其允许公开的信息，联系方式通过本人选择的联系流程提供。

### 3.2 课程表

- 今日视图：课程、起止时间、教室、教师、周次与备注。
- 周视图：星期、节次与课程块；点击显示完整课程信息。
- 设置学期起始日期、作息节次、当前周；支持单周、双周、指定周次与不同周次不同教室。
- 导入入口：截图识别、支持格式的课表文件、手动录入。明确展示支持的文件类型。
- 导入流程：选择来源 → 识别预览 → 标出缺失和不确定字段 → 用户修正 / 确认 → 保存。
- 校验时间、周次和重复课程；不确定的信息不自动编造。冲突先提示，允许核实后保留。
- 支持修改、删除、临时调课和多学期切换。一次导入不宣传为自动同步教务变更。
- 课程提醒需用户主动开启，实际能力根据首发载体验证；不将“绝不漏提醒”作为承诺。
- 个人课表默认私密。共享须明确选择内容与对象；活动匹配只需可用时间，不公开完整课表。
- 后续按活跃学校适配教务直接导入；不将全国教务系统适配作为首版依赖。

### 3.3 二手交易

- 出售与求购两种发布类型；教材、宿舍用品、数码配件、运动兴趣等分类可配置。
- 出售字段：实拍图片、标题、价格、规格 / 版次、成色、已知缺陷、校区、公共交接地点、可交接时间。
- 求购字段：物品要求、预算、校区与期限。支持关键词和求购订阅提醒。
- 列表展示图片、标题、价格、状态和交接区域。只展示有来源依据的时间或距离，不推测用户位置。
- 联系卖家、收藏、预约交接、完成确认与评价；避免把“联系过”直接统计成成交。
- 商品状态：草稿 → 审核中 → 在售 → 已预约 → 已售 / 下架；预约取消后可返回在售。
- 提醒卖家确认商品是否仍在售。统计中区分本站确认成交、卖家自行标已售与状态未知。
- 首版可采用当面验货、双方直接付款的模式；清楚标注平台是否提供交易担保。普通发布暂按免费设计。
- AI可辅助标题、分类与描述，所有规格、价格、缺陷和成色由卖家确认。二手付费推广可后续测试。

### 3.4 校园跑腿

- 首版保留跑腿完整模块。每个试点校区先配置一种或少数服务，例如快递代取、校内物品代送。
- 发布字段：服务类型、取件与交付区域、重量 / 尺寸、时间要求、费用与必要备注。
- 快递取件码、具体宿舍和联系方式仅向必要的订单参与人展示，不出现在公共接单列表。
- 下单前显示总费用、平台服务费与履约规则；接单者看到预计实际报酬。
- 接单者申请与审核、可服务校区、接单开关、同时接单上限及服务时段。
- 状态：待支付 → 待接单 → 已接单 → 已取件 → 待确认 → 已完成；另设取消、超时、退款和申诉。
- 无人接单、超时、接单者退出、物品异常均有明确处理入口和记录。
- 真实收费上线时必须接通支付、取消退款、结算与对账，并防止重复支付、重复接单或重复结算。演示版只模拟这些状态。
- 订单完成确认与评价；费用争议、损坏或丢件可提交证据，由运营处理并保留记录。
- 不承诺自动找到骑手。无可用服务时段或接单能力时，限制预约 / 下单，明确展示原因。
- 定位轨迹、自动派单、跨校区配送和复杂代购作为后续扩展。

### 3.5 线下活动

- 首版支持球局、桌游、社团活动等，活动分类由试点校区配置。
- 活动内容：组织者、时间、公共地点、人数上限、费用、报名截止时间、参加要求和取消说明。
- 发布审核、报名、名额候补、取消报名、名单管理、活动变更通知、签到和结束反馈。
- 用户允许后提示活动与课表是否冲突，不自动报名。
- 活动状态：草稿 → 审核中 → 报名中 → 已满 / 截止 → 进行中 → 已结束；支持取消及通知。
- 免费活动可以先开放；收费活动上线前补齐收款、取消退款和组织者结算流程。
- 组织者可以管理必要名单；公开列表不显示参加者联系方式或完整日程。
- 线下场地安排、活动要求由组织者与当地运营核实，系统记录相关状态。

### 3.6 消息与个人中心

- 交易和订单消息带来源卡片，可直接回到商品、订单或活动。
- 通知分为需要处理和普通更新；红点仅用于真实未读事项，不制作虚假活跃提示。
- 支持消息屏蔽、举报、通知偏好和发送失败重试。首版会话以文字与图片为主。
- 我的发布：出售、求购、跑腿、活动；我的参与：购买预约、跑腿订单、活动报名。
- 接单者和活动组织者在获得权限后显示对应工作入口，普通用户不承担额外界面复杂度。
- 设置：默认首页、字号、课表设置、隐私和通知、账户注销与数据处理入口。

## 4. 运营后台与权限

后台不依附某一所学校定制，平台管理员与校区运营分开授权。

| 能力 | 首版要求 |
| --- | --- |
| 学校与校区 | 开通、暂停、服务分类、服务时段、公共交接地点和规则配置 |
| 用户与角色 | 认证审核、接单者审核、组织者权限、屏蔽与申诉 |
| 内容管理 | 商品、求购、活动、图片与举报审核；记录处理原因 |
| 订单运营 | 跑腿进度、超时异常、取消退款、结算对账及凭证 |
| 客服处理 | 关联用户、订单和证据的工单，责任人和处理状态 |
| 财务统计 | 交易额、平台收入、接单报酬、退款和补贴分别统计 |
| 业务统计 | 导入成功率、留存、有效询问、确认成交、接单与完成率、活动成行率 |
| 权限与记录 | 校区数据隔离、敏感字段最小可见范围、关键操作日志 |

校方如参与试点，可按具体合作范围提供汇总统计或有限管理权限；不默认向校方开放学生私聊、课表与全部个人资料。

## 5. 手机端视觉规范

视觉关键词：清楚、安静、熟悉、轻量。借鉴微信的导航与列表习惯，使用独立品牌与图标，避免直接复制其标识。

| 项目 | 建议规范 |
| --- | --- |
| 页面背景 | 浅灰 #F5F6F7；内容区域白色 #FFFFFF |
| 主文字 | #202522；次级信息 #69736D；避免大面积浅灰小字 |
| 主色 | 青绿 #07855D；用于主要按钮、选中状态与可操作文字 |
| 状态颜色 | 红色用于错误与必要提醒；价格可用低饱和暖色；同时用文字说明状态 |
| 正文字号 | 默认16px，系统中文字体；可选更大字号 |
| 标题字号 | 页面标题18—20px；列表标题16—17px |
| 辅助字号 | 时间与说明13—14px；底部导航12px；重要信息不用小字 |
| 字重 | 正文400，标题与重点500；避免整页粗体 |
| 行高 | 正文约1.5倍；标签与按钮按控件高度保持垂直居中 |
| 页面间距 | 左右16px；内容间隔8 / 12 / 16 / 24px |
| 圆角 | 8—12px；减少圆角容器嵌套 |
| 列表 | 白底、细分隔线、左内容右操作；二手用紧凑图片列表 |
| 图标 | 同一套线性图标，导航约22—24px；图标与文字同时出现 |
| 触控区域 | 至少44×44px，主按钮高48px；相邻操作保持间距 |
| 底部导航 | 四个等宽入口，约56px加设备安全区；选中主色，其他中性色 |
| 动效 | 短促反馈和自然页面过渡；不采用循环装饰动画 |

首版优先完成浅色模式，深色适配保持同一信息层级。避免大幅营销横幅、满屏彩色功能宫格、强制弹窗、自动轮播和悬浮广告。

## 6. 核心页面与操作规则

- 校园页：校区在顶部；右上角发布入口；搜索；可关闭的下一节课摘要；二手 / 跑腿 / 活动分类；对应列表。
- 发布入口随当前分类变化，直接进入卖闲置、发布跑腿或发活动；二手内可选择出售 / 求购。
- 商品详情：图片、价格、已知状态、描述、交接信息；主要操作为联系卖家。
- 跑腿详情：取送范围、物品条件、期限、报酬、当前进度；接单前确认具体承诺。
- 活动详情：时间、地点、组织者、费用、余位和取消规则；主要操作为报名。
- 表单先填写必要字段，补充信息折叠；输入错误就近说明；草稿自动保留。
- 有网络、空内容、无权限、未开放和失败状态；支持重试、返回与客服帮助。
- 删除、取消订单、退款等影响结果的动作确认后执行；一般浏览和切换不增加确认弹窗。
- 支持320—430px常见手机宽度、系统字号放大、键盘弹出和底部安全区，不依赖悬停操作。

## 7. AI的使用边界

AI嵌入具体任务：课表识别、商品描述、分类与求购匹配、活动信息整理、内容审核辅助和运营摘要。

首版不以聊天机器人作为首页。重要价格、时间、商品状态和订单操作需要用户确认；争议处理保留人工入口。不得使用虚构商品、虚假报名、模拟交易量或无依据的“智能估价”制造市场活跃度。

## 8. 首版范围与交付验收

四个业务模块均包含在产品范围内。通用结构支持多学校，实际服务按校区配置开放。

演示版验收：导航可用，主要详情和操作路径可以体验，演示状态明确；不声称已收款、实际接单或实际报名。

真实试点版验收：登录与身份权限、实际数据存储、消息、审核、角色隔离、异常状态可用。任何真实付费功能必须完成支付、退款、结算和对账验证，不能以界面上有支付按钮代替。

必要检查：

1. 课表导入中的单双周、跨周变化、缺失字段和冲突课程可核对并修正。
2. 跑腿同时接单仅一人成功；重复提交不产生重复扣款；取消与退款状态可追踪。
3. 活动满员后不会超额报名；取消后余位正确恢复。
4. 不同校区、不同角色不能越权查看私聊、取件码和认证材料。
5. 320px宽度与放大字号下无文字重叠或主要按钮遮挡；各页均有加载、空状态和失败处理。
6. 统计区分发布量、已售标记与本站确认成交，区分流水、平台收入和可分配利润。

后续扩展：活跃学校教务适配、原生桌面课表组件、二手担保与代卖、复杂跑腿调度、活动商业合作等，按真实需求分别评估。

当前仍需试点确定：首个校区、服务费用、接单者报酬、认证方式、支付与结算接入条件、客服责任人以及校园内实际服务边界。以上不妨碍先完成通用产品和交互设计。
