# 详细模块架构：工程约定与独立验收规范

版本：v1.1，2026-09-17。状态：设计完成后交付实施，所有验收条目均为待执行要求，不表示已经通过。

## 1. 拆分含义

保留原架构 M00–M11 十二个大模块，子模块编号使用 Mxx.yy。子模块是可单独分派、实现、审查和验收的代码责任单元，不要求成为单独服务、数据库或 Maven 项目。共享同一个业务聚合的子模块共用领域模型，通过聚合方法修改状态，不能各自复制一套状态字段。

总体技术栈、开源仓库与许可沿用父级《校园助手技术架构》《开源复用选型清单》。本轮细化不重新选择框架，不把待实现类名说成上游现有代码。下文类、目录、接口和扩展表均是拟定的实现契约；落码时匹配固定版本上游，避免建立同义用户／支付主表。

## 2. 每个子模块必须交付什么

每个子模块包含目标与边界、内部工程结构、数据与不变量、接口契约、执行与失败处理、依赖与替身、独立验收七项。执行者还需交付代码、公开契约、必要迁移、测试数据、验收记录及已知限制。所列接口至少明确关键输入、输出和错误语义，正式字段清单落入 OpenAPI 或内部类型定义。

后端按职责建立 controller → application → domain → infrastructure，公开入口置于 api；简单功能使用包级边界，不机械生成五个工程。前端使用 page → composable/store → api-client，并共用主题与基础组件。外部 SDK 位于适配器，业务域不暴露其原生 DTO。

命名空间为计划的仓库根目录下的相对路径，用于未来落码，不表示当前目录已存在。表归属以大模块为界，子模块注明唯一写入职责；同一聚合的领域类由聚合责任子模块维护，其他子模块调用公开命令或经约定的聚合方法。

## 3. 公共接口和数据约束

- ID 在 JSON 中使用字符串；金额使用整数分和币种。请求中的 owner、金额、学校授权不能覆盖服务端事实。
- 技术时间保存 UTC；课表保留学校时区、当地日期和周次。可注入 Clock 供测试使用，不依赖等待真实时间。
- 敏感写操作带 Idempotency-Key、必要的 expectedVersion；同键异体冲突，同键同体返回原结果。数据库业务唯一约束不依赖幂等键保留期限。
- 响应统一 code、message、data、traceId；列表有分页上限。表格中的错误名称为稳定业务语义，数值编码在 M00.02 冻结。
- 资源级权限覆盖单条／列表／批量／导出／附件／WebSocket；跨校仅公开浏览按配置允许，不能因此访问私有字段。
- 业务写入与 outbox 同事务；消费者标记与内部效果同事务；外部副作用有稳定业务单号并可查证。异步租约过期后旧执行者不能覆盖新执行者结果。
- 争议受理与财务冻结同数据库事务；尚未创建结算时也保留冻结。不得用异步通知代替立即生效的资金控制。
- 跨域操作调用公开 API，不直写其他域表；只读统计有明确授权且可重建。学校运营角色不会自然获得财务权限或全体学生私有数据。

## 4. 依赖不齐时如何独立验收

独立验收分为三层，记录不得混淆：

| 层级 | 环境与目的 | 能证明什么 |
|---|---|---|
| A：子模块验收 | 本模块真实代码；相邻模块使用符合契约的 stub；涉及锁／唯一约束时使用真实 MySQL | 本模块规则、输出契约、权限调用和失败恢复满足指定场景 |
| B：集成验收 | 相邻模块、数据库和缓存使用真实实现；微信等外部渠道可用受控适配器 | 跨模块事务、契约、状态与事件协同正确 |
| C：外部／真机验收 | 微信真机、真实存储及获批支付渠道；受控小额资金 | 平台权限、SDK、网络和实际到账等外部行为成立 |

A 通过即可独立交接，不能据此宣布业务已可上线。后台样式等低风险改动用人工验证即可，不强迫每个组件写镜像式测试；并发、权限、幂等和资金必须有可重复的自动化证据。完整发布仍需相应 B、C 验收。

Stub 使用版本化固定样例，包含成功、拒绝、超时、重复、乱序结果；真实实现必须通过同一契约用例。Mock 只验证交互不能证明数据库锁正确，内存库不能替代资金／名额／接单并发验收。

## 5. 验收记录格式

```text
子模块：Mxx.yy；实现提交：<sha>；契约版本：<version>
执行层级：A / B / C
环境：JDK/Node、数据库、缓存、适配器及固定版本
前置数据：fixture ID；学校/用户/订单范围；时间与配置
操作：命令或界面步骤；并发数；故障注入点
预期：响应、数据库终态、事件数量、外部调用次数
实际：测试报告或脱敏截图；数据库断言；traceId
结论：通过 / 未通过 / 外部条件未具备
限制：尚未验证的相邻模块或第三方；清理与重跑方式
```

单元／集成测试按 Mxx.yy 标记或独立测试类选择器运行；M00.06 建立统一验收入口，使执行者不必运行所有业务才能验收一个小模块。本文不提供尚不存在的“已可运行命令”。

## 6. 共享固定样本

使用学校 S1、S2，S1 两个校区 C11／C12，S2 一个校区 C21；学生 U1／U2 属于 S1，U3 属于 S2；有效跑腿员 R1、停用跑腿员 R2；校级运营 O1／O2 和独立财务角色 F1。每个样本有固定 ID 与初始化脚本，禁止复制真实证件或令牌到仓库。

并发验收使用可控起跑屏障，重复运行并检查数据库与外部副作用，不以“发了 100 个请求未报错”代替正确性证明。日期、随机数、渠道事件 ID 和网络故障都可固定或注入。

## 7. 多人或多 AI 实施规则

每个任务明确拥有的目录、公开契约与迁移编号。共享代码库中的执行者不得回退他人修改；公共模型、资金、权限、事务和契约变更由架构负责人复核。相邻模块可以先按契约独立实现，联调时修复兼容性，不能直接跳过未通过的检查。

子模块“已完成”须附 A 级证据及待 B／C 项；大模块完成须附跨子模块 B 级证据；产品发布依照原 P0–P4 阶段并补足必要 C 级证据。
