# M00 工程底座：六个可独立交付子模块

本文件是待实施工程契约，遵循 [工程约定与独立验收规范](00-工程约定与独立验收规范.md)。目录、类和测试入口均为拟建，不表示已有代码或验收已通过。

## 共享数据、内部边界与依赖

- 复用芋道框架、system、infra；member、pay 由对应业务按需启用。统一依赖与启动配置归 M00.01，公共 API 规范归 M00.02，SQL 迁移制度归 M00.03。
- `campus_idempotency` 仅 M00.04 写；`campus_outbox`、`campus_event_consumption` 及领取状态仅 M00.05 写。业务经公开接口参与同一数据库事务，不能直接操作调度状态。
- 计划在 `backend/campus-common/` 承载少量契约、事务和测试支撑；是否独立 Maven 工程由依赖图决定。避免把所有业务工具堆入 common。各业务保留自身表、状态机与查询。
- `contracts/` 是 HTTP、事件和适配器契约入口；`database/migrations/` 是增量 SQL 唯一入口。上游物理表映射先冻结，再编写自有迁移。
- 工程底座提供机制，不替业务决定订单合法状态、身份授权和外部支付结果。A 级用真实 MySQL 与最小示例聚合验证机制；B 级检查真实业务接入；C 级仅适用于实际构建平台与外部环境。

## M00.01 开源底座与依赖锁定

**目标与边界：** 把选定开源项目变为可重复构建的最小底座。沿用 ruoyi-vue-pro、配套管理端、unibest 与 Wot UI，不重写账号框架或组件库；此项负责依赖组合与裁剪，业务页面和功能仍归各模块。

**工程结构：** 在 `docs/adr/0001-upstream-baseline.md` 记录源码 SHA、分支、补丁、许可证；`backend/pom.xml` 固定编译与依赖版本；`apps/*` 保留包管理锁文件；`deploy/dev/` 描述 MySQL、缓存与本地存储。拟建 `StartupConfigurationGuard` 校验运行 profile，启动链为加载配置 → 验证必需变量 → 初始化依赖 → 健康检查。

**数据与不变量：** 不建业务表；构建产物必须能追溯到源码与依赖清单。同一次发布不得引用浮动 SNAPSHOT 或 latest 镜像而无固定解析结果。Java 基线按原架构先验证 Java 17；变更 Java 或 Spring 主版本必须留独立记录。保留第三方许可，禁止提交真实密钥与默认生产密码。

**接口契约：** 交付构建说明、环境变量模板、依赖清单及健康检查；`/health/readiness` 只给必要状态，内部详情需鉴权。缺数据库配置或生产启用模拟支付时启动失败，错误标识为 `CONFIGURATION_INVALID`，日志仅含变量名。

**执行与失败处理：** 清洁环境先解析固定依赖、执行迁移，再启动。Valkey 与上游缓存客户端必须跑协议及锁操作兼容检查；不通过时记录并切换已验证兼容服务端，不能悄悄改业务语义。外部暂时不可用按依赖级别使 readiness 失败或限定功能不可用。

**依赖与替身：** 无业务依赖；对象存储、微信和支付使用显式测试适配器。复用代码对应许可证与补丁位置纳入清单，不能把 README 的宣传当作兼容证明。

**独立验收：** A：两次全新目录按锁定清单构建，依赖解析版本一致且产物可追溯；删除必需数据库变量，启动拒绝且日志无秘密；启用生产 profile 加模拟网关，启动拒绝。B：真实最小前后端启动，数据库和缓存读写成功，无 ERP／CRM 等非选模块运行依赖。C：构建出的微信小程序在真机打开，记录工具链及基础库版本；云存储／支付权限另列未验项。

## M00.02 API 契约与错误规范

**目标与边界：** 统一入口、类型、错误和事件格式，使前后端及替身能够独立实现。此项维护公共协议与兼容检查，不替各业务决定字段、授权规则或状态转移。

**工程结构：** 拟建 `contracts/openapi/app.yaml`、`admin.yaml`、`contracts/events/` 和 `contracts/stubs/`；公共包提供 `CampusResponse`、`CampusError`、`EventEnvelope`、`TraceContext`。控制器绑定请求 DTO → 参数校验 → 应用用例 → 统一异常映射；生成的 TypeScript 客户端供 M10／M11 使用，禁止前端复制另一套手写金额和 ID 类型。

**数据与不变量：** JSON ID 为字符串、金额为整数分、时间使用明确格式。响应固定 `code/message/data/traceId`；成功也有 traceId，私有资源拒绝不泄漏存在性。错误码语义稳定；分页设置默认值与硬上限。事件须含 eventId、type/version、aggregateId/version、schoolId、occurredAt；载荷禁止证件和取件码。

**接口契约：** 入口为 `/app-api/campus/v1`、`/admin-api/campus/v1`，外部回调独立定义。HTTP 与业务码映射明确：参数错误 400、未认证 401、无操作权限 403、隐藏资源 404、版本／幂等冲突 409、限流 429。409 在已获授权情况下返回 `currentVersion/currentState`；重试提示区分可重试与需用户修正。

**执行与失败处理：** 在控制器边界做类型转换，领域异常由统一处理器映射，未知异常输出脱敏 500 并保留 trace。发布契约先检查向后兼容；删除字段或改变含义需新版本及迁移窗口。事件消费者对未知版本进入可观察失败，不按旧结构猜测执行。

**依赖与替身：** 复用上游响应、校验与 OpenAPI 能力，通过小适配满足本项目规范。每个适配器提供成功、拒绝、超时、重复与乱序样例；相邻团队共同使用同版本样例。

**独立验收：** A：大于 JavaScript 安全整数的 ID 往返保持原字符串；金额传小数或超分页上限得到约定 400；无效参数与未捕获异常均带 traceId，响应无堆栈。B：同一真实端点及 stub 通过契约用例，生成客户端可编译并识别 409；未知事件版本不改业务表。C：真机请求核对 HTTP 状态与响应解析，不要求微信支付实际开通。

## M00.03 数据库迁移与事务约定

**目标与边界：** 建立可审计迁移及事务边界，保证并发规则可在真实 MySQL 验证。M00 定制度与工具；各业务拥有自身迁移和聚合写入，不允许公共层代写订单表。

**工程结构：** `database/migrations/` 采用单调版本与模块编号，拟定 `V<序号>__Mxx_<说明>.sql`；复用所选迁移工具执行，落码前固定一种。`docs/transactions.md` 维护锁顺序、事务传播与重试白名单；公共 `TransactionExecutor` 仅封装有界重试，领域用例明确 `REQUIRED`，事务外网关调用由 outbox 驱动。

**数据与不变量：** 迁移有 checksum，生产禁自动建表；唯一键、版本列和索引由 SQL 保证。时间 UTC、货币整数分；跨域同步命令加入调用方事务，禁止意外 `REQUIRES_NEW` 导致半提交。锁顺序按业务流程统一，资金控制记录、身份资格锁及订单锁的先后由跨模块契约冻结，不能由各实现者独立猜测。

**接口契约：** 交付 `MigrationPlan(fromVersion,toVersion,backupPrerequisite)` 与 `TransactionPolicy(operation,retryableErrors,maxAttempts)`。缺历史版本、checksum 不符、危险破坏迁移输出 `MIGRATION_BLOCKED`；乐观锁失败转 `VERSION_CONFLICT`，死锁达到上限转可查询的 `RETRYABLE_CONFLICT`。

**执行与失败处理：** 增量变更优先扩展字段 → 双版本兼容 → 切换 → 后续清理。DDL 不假定可事务回滚，失败先检查实际 schema 和迁移记录，再采用前向修复。死锁重试必须重跑整个业务事务，并复用幂等键；已发生外部副作用不能纳入自动事务重试。大批量操作分批带游标。

**依赖与替身：** 依赖 M00.01 数据库版本与 M00.04 幂等。A 使用真实 MySQL 容器或隔离实例；相邻域使用加入同事务的 stub 表，不用内存库证明锁正确。

**独立验收：** A：空库和上一个发布版本均升级至相同 schema；篡改已执行迁移触发阻断；注入第二次写入异常，示例业务表及 outbox 均无半提交。B：真实业务跨域事务失败后各自表一致回滚，100 个并发请求的唯一约束成立；旧应用读取扩展后的 schema 正常。C：在预发演练失败迁移恢复，记录备份与前向修复证据；生产恢复由 M11 负责。

## M00.04 幂等命令

**目标与边界：** 为敏感写请求提供重试一致性，避免双击、弱网和进程重启重复业务效果。它只控制同一命令的重复执行；订单、报名及资金自身仍需独立业务唯一约束。

**工程结构：** 拟建 `campus-common/idempotency/`，含 `IdempotentCommandExecutor`、`RequestCanonicalizer`、`IdempotencyRepository`。控制器解析键 → 应用层提供 actor/action 与标准化输入 → 执行器检查摘要 → 业务事务执行 → 保存结果。不得用拦截器在业务事务提交前单独标为成功。

**数据与不变量：** `campus_idempotency` 唯一 `(platform_tenant_id,actor_id,action,key_hash)`，含 request_hash、状态、业务引用、结果版本和有效期。摘要基于约定字段标准化，不把 traceId 纳入；同键异体永远不能复用旧结果。成功结果与业务写入原子提交；长期结果可只存引用并经授权重建，避免敏感响应永久缓存。

**接口契约：** `execute(actor,action,key,canonicalRequest,handler)` 返回首次结果或 `replayed=true` 的同义结果。异体返回 `IDEMPOTENCY_CONFLICT`；仍执行中返回 `COMMAND_IN_PROGRESS` 和查询方式，不能再次启动 handler。身份与资源权限在重放返回前重新校验，已撤权不能借旧键读敏感结果。

**执行与失败处理：** 普通数据库命令在同一事务插入占位、执行 handler、写结果；并发请求由唯一键和锁竞争串行。回滚则占位同步回滚。外部调用类命令只幂等创建持久任务并返回受理结果，由网关稳定单号完成后续；不能把网络调用包成长事务。保留期清理不删除业务唯一键。

**依赖与替身：** 依赖 M00.02／.03，使用注入 Clock 和示例 `CounterCommand`；身份授权提供允许／拒绝 stub。支付、报名等业务需定义自己的 action 与标准化输入，不由公共层反射猜测。

**独立验收：** A：50 个同键同体并发，返回同业务 ID，真实 MySQL 仅一行业务结果和一个事件；同键更改金额返回 409，数据库不新增；提交前杀进程后重试可完成一次。B：权限撤销后重放既有成功键返回拒绝，不泄漏旧响应；幂等记录清理后真实报名／支付业务唯一性仍成立。C：真机断网后重发订单返回原订单；不以客户端禁止双击代替服务器验收。

## M00.05 outbox 调度与恢复

**目标与边界：** 提供至少一次异步交付、去重、恢复和人工重放。此项处理运输与执行调度，不承诺网络恰好一次，也不能替代争议受理时同步资金冻结。

**工程结构：** 拟建 `campus-common/outbox/`：`OutboxPublisher` 加入业务事务；`OutboxClaimJob` 用短事务抢占到期记录；`EventHandlerRegistry` 按 type/version 路由；`ConsumerExecutor` 记录去重与错误。API／worker 可同进程或多进程，共用数据库领取机制。

**数据与不变量：** `campus_outbox` 含 event_id、载荷版本、next_run_at、attempt、lease_until、lease_token、status；`campus_event_consumption` 唯一 `(consumer,event_id)`。事件表不可保存原始证件。每次领取递增 fencing token；完成、续租和失败更新均要求 token 与当前值一致。内部消费者效果与成功标记同事务。

**接口契约：** `publish(EventEnvelope)` 要求已有事务；handler 返回完成、可重试、永久失败。`replay(eventId,consumer,reason,expectedVersion)` 保留原事件 ID，已成功消费者跳过；另发修正事实使用新事件。错误按 `UNKNOWN_EVENT_VERSION/RETRY_EXHAUSTED/LEASE_LOST` 展示，管理查询不直接暴露敏感载荷。

**执行与失败处理：** 抢占事务可使用 `FOR UPDATE SKIP LOCKED`，提交后执行任务；旧 worker 租约过期不能覆盖新结果。重试指数退避加抖动，超限进人工队列。外部调用必须有稳定业务单号、可查询状态和幂等能力；fencing 只保护本地写入，不能阻止已发出的外部请求。乱序业务事件由领域版本规则处理，缓存广播只是加速提示。

**依赖与替身：** 依赖 M00.03／.04；使用受控 handler 注入超时、崩溃与外部结果未知，实际 MySQL 验证抢占。M11 提供看板，具体外部补偿归业务适配器。

**独立验收：** A：两 worker 抢同记录且旧 worker 过期后回写，旧 token 更新零行；处理完成后 ACK 前崩溃，重放仍只有一条内部效果；连续失败进入死信并保留原因。B：业务提交失败无事件，真实消费者重复收事件不重复通知／记账；数据库提示丢失后扫描仍能领取。C：真实外部适配器请求超时后以原业务号核实结果；不支持幂等的提醒渠道必须明确重复风险及去重限制。

## M00.06 测试夹具与持续集成

**目标与边界：** 让每个子模块能按编号独立验收，并把必须通过的权限、并发、资金检查接入 CI。此项建工具与证据格式，不代替各模块设计领域场景，也不为低风险样式强制写镜像测试。

**工程结构：** 拟建 `tests/fixtures/common/`、`contracts/stubs/`、后端各模块 `src/test/` 和 CI 工作流；公共 `CampusFixtureFactory`、`MutableClock`、`ControlledGateway`、`ConcurrencyBarrier` 支持固定身份、时间和故障。验收选择器以 Mxx.yy 标签运行，构建说明列出实际可运行命令后才交付。

**数据与不变量：** 固定 S1/S2、C11/C12/C21、U1/U2/U3、R1/R2、O1/O2/F1 样本；每次运行使用隔离数据库或独立前缀，清理不能触达生产。报告记录源码 SHA、迁移版本、依赖、层级 A/B/C、用例和未验项；stub 契约版本与真实适配器一致。测试不用真实学生证、密钥或手机号。

**接口契约：** 流水线输入提交与所选模块，输出构建、契约、关键测试、迁移与依赖扫描报告。验收状态为 `PASS/FAIL/EXTERNAL_NOT_READY`；外部条件不足不得变为成功。必需步骤未执行或进程异常退出视为失败，不能只看最后命令退出零。

**执行与失败处理：** 基础检查后按受影响模块运行；涉及公共权限／事务契约变更扩大到关键集成集。资金和名额并发使用真实 MySQL、起跑屏障及终态断言。重试测试只能诊断不稳定原因，不能把随机多跑一次成功当作通过；外部联调在隔离环境人工或受控触发，记录清理结果。

**依赖与替身：** 依赖 M00.01–.05。优先复用上游测试框架和容器测试能力；相邻模块实现未齐时使用版本化 stub，不能把一个类的 mock 调用次数当作跨域提交成功证据。

**独立验收：** A：只选 M00.04 可在新库运行并生成对应报告；故意删除唯一约束后并发用例失败；故意抛出未捕获异常时 CI 阻断。B：把 stub 换真实邻域后同一契约集通过，跨校样本稳定复现拒绝和零副作用；敏感测试数据扫描无真实凭证。C：真实微信与支付验收证据单独归档，缺少商户权限时标 `EXTERNAL_NOT_READY`，发布门禁不得误判已完成。
