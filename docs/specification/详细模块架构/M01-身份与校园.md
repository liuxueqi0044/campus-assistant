# M01 身份与校园：六个可独立交付子模块

本文件是待实施工程契约，遵循 [工程约定与独立验收规范](00-工程约定与独立验收规范.md)。复用上游 member、system 与微信身份接入；不另建一套同义用户和管理员主表。

## 共享数据、内部边界与依赖

- `backend/campus-module-identity/` 管理学校身份扩展。微信映射优先复用上游合理表；自有 `campus_school/campus_campus` 归 .02，`campus_membership/campus_verification` 归 .03，`campus_operator_grant` 归 .04，`campus_runner_qualification` 归 .05。账户状态映射及资源授权语义归 .06。
- `school_id/campus_id` 是业务范围，第一阶段平台 `tenant_id` 由服务端固定。客户端校区选择与认证、管理员授权三个概念必须分离。
- `IdentityApi`、`CampusScopeApi`、`MembershipApi`、`RunnerQualificationApi` 是公开入口。业务资源策略接口置于公共 api 包，由各业务实现 `ResourcePolicyProvider`，启动模块装配；identity 不导入课表、订单或消息实现。
- 依赖 M00。认证材料由 M02 提供端口适配；M01 的应用层仅依赖媒体契约，不能与媒体实现形成 Maven 循环。到期判断读取有效期和权威状态，不等待后台到期任务。
- 所有状态变更有操作者、理由、版本和追加日志。校园管理员只有显式学校范围与动作权限；手机号、微信绑定和校园认证互不替代。

## M01.01 微信登录与身份绑定

**目标与边界：** 将合法微信身份绑定为唯一内部学生身份，完成登录、续期和退出。复用上游登录／Token 实现；不把微信登录直接等同学校认证，不要求 UnionID 必然存在，不在此维护后台账号。

**工程结构：** 拟建 `controller/app/WechatLoginController`、`application/LoginApplicationService`、`api/IdentityApi`、`infrastructure/WechatIdentityAdapter` 和 `MemberAccountAdapter`。请求 code → 微信适配器交换 → 标准身份结果 → 事务查建绑定 → 上游 Token 签发；渠道原生 DTO 不进入业务模块。

**数据与不变量：** `(appid,openid)` 数据库唯一，映射到已有 member_id；UnionID 仅在可信返回且合并策略明确时用于关联，冲突进入人工处理，不自动合并已有资产账号。code、session_key、访问 Token 不入普通日志；服务端不接受前端自报 openid。学生与后台 Token 的受众和鉴权入口分开。

**接口契约：** `POST /auth/wechat/login {code,clientContext}` 返回 `accessToken,expiresAt,userId,profileCompletion`；appId 从服务端已登记客户端解析。无效 code 为 `WECHAT_CODE_INVALID`，渠道超时为 `IDENTITY_PROVIDER_UNAVAILABLE`，账号停用为 `ACCOUNT_DISABLED`；刷新、退出沿用已固定上游协议并补充文档。

**执行与失败处理：** 微信交换发生在数据库事务外，成功后才查建身份。并发唯一冲突回查既有绑定，不能另建孤立 member。绑定事务失败不签发有效会话；未知渠道结果要求客户端重新获取 code，禁止无限重用一次性 code。Token 退出与账户 authVersion 校验通过上游适配实现。

**依赖与替身：** 依赖 M00、上游 member 与 M01.06 账户状态；微信适配器 stub 覆盖无 UnionID、重复身份、无效 code、超时和身份冲突。

**独立验收：** A：两个不同合法 code 返回同一 openid，并发登录只产生一个成员及绑定；伪造 openid 字段不改变渠道事实；无效 code 不写成员或登录成功事件。B：学生 Token 访问后台得到 401／403，退出后旧会话拒绝，现有用户登录不覆盖认证关系。C：微信真机完成首次和再次登录，记录绑定一致；日志检查没有 code、session_key 或完整 Token，渠道不可用时页面可重试。

## M01.02 学校校区与浏览上下文

**目标与边界：** 管理学校／校区目录及用户当前浏览位置，向页面提供可用功能上下文。学校目录是平台维护数据；定位、选择校区、加入学校意向均不能授予已认证权限。

**工程结构：** 拟建 `domain/School`、`Campus`、`application/CampusContextService`、`api/CampusScopeApi` 与 `SchoolRepository`。学生请求上下文 → 身份与目录读取 → 结合有效认证及功能配置 → 输出只读上下文；学校配置写入口由后台权限保护，业务模块通过 api 校验学校校区归属。

**数据与不变量：** .02 唯一写 `campus_school/campus_campus`；校区必须关联存在学校，停用不删除历史订单引用。用户浏览偏好保存于明确扩展字段／表，不写 `campus_membership`。时区、学校名称、校区状态和配置版本必填；服务端平台租户值不来自请求头。目录变更保留版本供缓存失效。

**接口契约：** `GET /schools?keyword&cursor` 返回公开目录；`GET /context` 返回浏览校区、身份状态和功能能力；`PUT /context {schoolId,campusId}` 只保存偏好。内部 `assertCampusBelongsToSchool`、`resolvePublicScope` 返回范围；校校区不匹配 `CAMPUS_SCHOOL_MISMATCH`，已停用 `CAMPUS_UNAVAILABLE`。

**执行与失败处理：** 配置写入与 `identity.campus_changed.v1` 同事务；缓存以版本失效，敏感动作再次读权威状态。浏览校区停用后返回明确不可用及可选项，不自动把用户迁到另一校并授予身份。跨校公开浏览由配置允许，私有 DTO 不因 browseScope 扩大而放宽。

**依赖与替身：** 依赖 M00、M01.01；认证状态端口与 M09 配置查询使用 stub，目录可先独立交付。不得反向直接读取运营配置实体。

**独立验收：** A：S1 与 C21 组合返回 400，偏好无修改；U1 切换 S2 后上下文显示仅浏览身份，membership 保持 S1；伪造 tenant header 不能访问其他平台数据。B：停用 C11 后新发布接口拒绝、历史订单仍可按业务权限读取和处理；缓存失效失败也不能新建停用校区业务。C：真机长校名、学校搜索与返回原页面恢复正确，公网目录不含管理员联系方式或学生资料。

## M01.03 成员认证生命周期

**目标与边界：** 管理学校成员关系从申请、审核到生效、过期、撤销的全过程。认证证明的是指定范围与期限；审核队列页面归 M09／M11，媒体检查归 M02，身份域保留最终认证状态写权。

**工程结构：** 拟建 `VerificationApplicationService`、`domain/Membership`、`VerificationAttempt`、`api/MembershipApi` 与 `VerificationMethodAdapter`。提交材料／邮箱证明 → 验证来源和附件状态 → 创建申请 → 授权审核命令 → 更新成员关系与事件。各认证渠道返回标准证明结果，不直接写有效成员。

**数据与不变量：** `campus_membership` 唯一 `(user_id,school_id)`，记录适用校区、有效期和版本；`campus_verification` 保存每次申请的来源、材料引用、状态与审核日志。申请被拒绝不能覆盖上一段仍有效资格；补充或重提生成新版本。到期检查用服务端 Clock，后台任务只同步展示状态和通知。

**接口契约：** `POST /verifications {schoolId,campusId,method,evidenceRefs}` 返回 applicationId/status；后台 `review(id,decision,reason,expectedVersion)`；`MembershipApi.check(user,school,campus,action)` 返回 effective、expiresAt、scopeVersion，错误为 `MEMBERSHIP_REQUIRED/EXPIRED/VERIFICATION_CONFLICT`。返回不含原始证件 URL。

**执行与失败处理：** 审核锁申请与成员关系，在同事务写决定、资格及 outbox；重复决定返回原结果，过时版本不得覆盖新决定。私有材料绑定通过媒体 api 加入规定事务或采用先绑定后确认的可补偿流程，失败不批准认证。撤销影响后续新敏感动作，历史订单的查询与善后通过专用权限继续。

**依赖与替身：** 依赖 M01.02/.04/.06、M00，媒体端口 stub 提供本人有效、他人、待检查和已删除文件。人工、邮箱及校方渠道都必须保留可验证来源。

**独立验收：** A：U1 绑定 U3 材料返回 `MEDIA_NOT_OWNED`，无申请；两名审核人相反决定并发仅一个版本提交，成员状态与事件一致；Clock 越过到期时 check 立即失效。B：真实媒体待检查不能批准，授权 O2 审核 S1 返回拒绝且无日志伪成功；撤销后新发布被拒绝，已有本人订单仍能善后。C：所启用真实邮箱／校方渠道分别核验伪造、过期证明；未接渠道明确保持关闭。

## M01.04 后台学校范围授权

**目标与边界：** 在上游 RBAC 上增加学校／校区与动作范围，保护列表、详情、批量、导出及运营指令。菜单可见性只服务体验，最终权限由服务端决定；财务权限与校园运营授权分开。

**工程结构：** 拟建 `OperatorGrantService`、`ScopePolicyCompiler`、`SchoolScopeQueryGuard` 和 `api/OperatorAuthorizationApi`。后台 Token → 上游角色校验 → grant 有效期／动作校验 → 服务端 scope → SQL 范围或资源授权。查询 guard 提供类型化条件，复杂联表及导出必须显式传 scope，不能只依赖拦截器猜学校列。

**数据与不变量：** .04 写 `campus_operator_grant`，含 admin_id、school/campus、action_set、expires_at、status/version；更改有审计。平台级授权必须是明确类型，不用 schoolId 为空隐式表示无限范围。所有受限查询至少同时满足平台租户、学校范围和资源级权限；缺 scope 默认拒绝。

**接口契约：** `authorize(operator,action,requestedScope)` 返回不可由客户端构造的 `AuthorizedSchoolScope`；`grant/revoke` 仅高权限管理动作。错误 `SCOPE_DENIED/GRANT_EXPIRED/ACTION_DENIED`；批量命令预检全量资源，任一越权整体拒绝，部分成功接口必须另行定义且不返回他校详细资料。

**执行与失败处理：** grant 更新与审计、权限版本同步事务提交。敏感命令读取权威 grant，缓存只是优化；导出任务保存请求人、操作和范围，执行及下载时重新鉴权，不能沿用已撤销授权。异步线程必须显式恢复受限上下文，缺失上下文阻断，绝不退化平台管理员。

**依赖与替身：** 依赖 M00、上游 system、M01.02/.06；业务列表以 S1/S2 示例表替身验证 SQL。各业务实现对字段脱敏负责，不由 scope 自动暴露财务明细。

**独立验收：** A：O1 只拥有 S1，按 ID 查询 S2 得隐藏资源响应；混合 S1/S2 批量命令整体拒绝且两校表零变化；无 scope 的自定义查询被阻断。B：真实列表、JOIN、导出、附件和统计均不泄漏 S2；撤销后队列中的导出任务失败且无可下载文件；O1 操作退款即使同校也因缺财务动作拒绝。C：后台真实部署验证学生 Token、跨环境 Token 与过期会话不能调用管理 API。

## M01.05 跑腿资格与停用

**目标与边界：** 管理跑腿员在学校／校区范围内的申请、批准、有效期与停用，并在接单时提供可并发保证的资格判断。订单负载、接单结果和历史履约归 M05，本项不得直接重写订单。

**工程结构：** 拟建 `RunnerQualificationService`、`domain/RunnerQualification`、`api/RunnerQualificationApi` 和资格仓储。`check` 供展示；`assertForAccept` 加入调用方事务并锁资格行，接单使用固定锁序“资格 → 订单 → runner_load”。停用事务只锁资格及写状态事件，不反向锁订单，后续订单处置走 M05 条件命令。

**数据与不变量：** .05 写 `campus_runner_qualification`，按 user/school 与明确 scope 唯一，含 status、有效期、批准人、停用原因、version；不存在资格不能被创建为默认有效。资格、成员认证和账户状态分别核对。权限停用先提交则新接单必须拒绝；接单先提交则作为已有订单进入处置范围，不能声称停用能撤销过去事务。

**接口契约：** `apply/approve/suspend/restore(expectedVersion,reason)` 管理资格；`assertForAccept(user,school,campus)` 返回 qualificationId/version 或 `RUNNER_NOT_QUALIFIED/RUNNER_SUSPENDED/RUNNER_SCOPE_DENIED`，要求活跃事务，错误 `TRANSACTION_REQUIRED` 不得降级成普通查询。

**执行与失败处理：** 审核及停用与日志、事件原子提交；账号或成员失效若需要同步禁止接单，由失效命令遵循同一资格锁协调，不能只发缓存失效事件。资格缓存不作为接单判定来源。停用事件可重试生成运营待办；已接任务仍有必要履约／证据／申诉访问，是否更换人员由订单规则处理。

**依赖与替身：** 依赖 M00、M01.03/.04/.06；M05 使用订单／负载 stub 可验证锁序。普通展示可读 stub，接单验收必须真实 MySQL 事务与行锁。

**独立验收：** A：R2 接单断言返回停用错误且无调用方订单修改；停用先锁提交、接单后执行，接单必拒绝；接单先提交、停用后执行，保留已有订单引用并产生一次停用事件。B：M05 的 100 并发接单及资格停用混合测试无越权新单、无锁顺序反转；资格过期即时拒绝，停用事件消费者离线不改变新接单拒绝事实。C：运营端停用后学生真机刷新显示资格状态与已有订单入口，不能显示全部订单已自动取消。

## M01.06 资源授权与账户生命周期

**目标与边界：** 统一私有资源访问语义，并处理账户停用、会话撤销和注销申请。M01 提供主体与策略执行框架；课表所有权、会话成员、订单参与关系由对应域策略判断，不能建立依赖全部业务实现的身份模块。

**工程结构：** 公共 api 定义 `ResourceRef`、`ResourceAction`、`ResourcePolicyProvider`；拟建 `ResourceAuthorizationService` 根据 type 调用注册策略，启动模块负责绑定。`AccountLifecycleService` 经上游账号适配更新状态、authVersion；`AccountObligationPort` 返回未结订单／资金等最小阻碍信息，不暴露领域实体。

**数据与不变量：** 账户状态复用上游合理字段并扩展映射，日志追加。拟定 ACTIVE 正常、LIMITED 禁止新增但允许本人善后、SUSPENDED 禁止学生侧操作并转运营处置、CLOSURE_PENDING 等待善后、CLOSED 完成关闭五种语义；Token 可用范围随状态检查，不靠是否持有 Token 推断。未知资源类型、缺策略或空主体一律拒绝；身份 scope 通过不代表私有资源通过。停用／注销不硬删账务与案件证据，公开资料与需保留数据分别处理。

**接口契约：** `authorize(actor,resource,action,purpose)` 返回 allow/deny 与审计标签，不返回敏感资源内容；`requestClosure` 返回申请状态、阻碍类别和后续路径；`suspend(reason,expectedVersion)` 返回账户新版本。错误 `RESOURCE_NOT_ACCESSIBLE/ACCOUNT_ACTION_RESTRICTED/CLOSURE_BLOCKED`；普通运营读取私有数据必须额外案件依据。

**执行与失败处理：** 状态和 authVersion 同事务变更，敏感入口查权威状态，会话断连是后续清理。涉及同步禁接单时先按固定顺序锁该用户资格，再更新失效事实，不持订单锁；禁止新增资格的检查需与生命周期命令协调。去标识化作为可恢复步骤任务，失败保留待处理状态，不误报已彻底删除。

**依赖与替身：** 依赖 M00、上游身份和 M01.04/.05；资源策略、未结事项端口均可 stub，业务域不反向导入身份实现。M02 私有下载和 M07 订阅复用同一授权入口。

**独立验收：** A：未知 type 默认拒绝，课表 owner stub 为 U2 时 U1 不能读取；账户停用后旧 Token 的敏感命令被拒绝；存在未结支付 stub 时注销返回阻碍且账户与账表无删除。B：真实课表、附件、聊天、导出执行相同资源规则；撤权后既有 WSS 订阅无法继续获得新消息；注销恢复任务重跑不丢证据。C：真机账户停用／退出后清理本地私有缓存，重新登录仍按服务端生命周期状态限制；人工核查敏感访问审计可定位案件与理由。
