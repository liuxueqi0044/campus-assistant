# M02 媒体与内容基础：五个可独立交付子模块

本文件是待实施工程契约，遵循 [工程约定与独立验收规范](00-工程约定与独立验收规范.md)。复用上游文件适配与 COS／OSS SDK，新增用途、绑定、权限与生命周期规则。

## 共享数据、内部边界与依赖

- 统一位于 `backend/campus-module-media/`。`campus_media_asset` 是共享聚合，包含 owner、用途、不可变对象 key、generation、物理状态、检查版本、可见性、到期与 version；`MediaAsset` 领域对象由 .02 维护，其他子模块经领域方法转换状态。
- .01 负责上传票据与存储端口；.02 唯一管理上传确认、文件有效性和业务绑定；.03 只管下载授权与访问日志；.04 管内容检查任务／判定记录；.05 管保留、保全与物理删除任务。扩展 `campus_media_binding`、`campus_media_inspection`、`campus_media_hold`、`campus_media_access_log`，不能由多个子模块各复制一份附件状态。
- 文件有效性检查与内容审核分别建模：格式正确不代表允许公开，审核通过不代表文件属于当前用户。所有文件先进入私有隔离区；公开商品图通过审批后可生成派生公开资源，私有原件不改成公共桶文件。
- 依赖 M00、M01 的身份／资源授权契约。媒体只保存 `resource_type/resource_id`，下载策略由领域 provider 判断，媒体不导入所有业务实现。业务表保存 asset_id，禁止存私有永久 URL。

## M02.01 上传票据与存储适配

**目标与边界：** 只允许用户为获准用途上传受限文件，并隔离云存储差异。复用上游文件存储与 SDK；本项不判断文件真实格式、是否允许发布或是否能成为纠纷证据。

**工程结构：** 拟建 `UploadTicketController`、`UploadTicketService`、`domain/UploadPolicy`、`api/StoragePort`、`infrastructure/CosStorageAdapter/OssStorageAdapter/LocalStorageAdapter`。身份及用途检查 → 分配 assetId 和不可猜测 key → 写待上传元数据 → 返回约束票据；统一存储端口只暴露上传、HEAD、读流和按版本删除等必要能力。

**数据与不变量：** 票据绑定 owner、purpose、最大字节数、允许类型、到期和独立 nonce；对象 key 包含环境与随机 ID，不由用户任意指定路径。私有用途包括认证、课表、聊天与跑腿证据。临时权限只覆盖单个 key，禁止授予列桶或任意删除。上传完成前 asset 状态为 `UPLOADING`，不得供发布使用。

**接口契约：** `POST /media/upload-tickets {purpose,fileName,size,mime}` 返回 assetId、uploadMethod、受限凭据／URL、expiresAt、requiredHeaders；owner 取登录事实。错误 `UPLOAD_PURPOSE_DENIED/FILE_SIZE_EXCEEDED/UPLOAD_QUOTA_EXCEEDED/STORAGE_UNAVAILABLE`。文件名仅作展示，不直接成为存储路径。

**执行与失败处理：** 数据库先记录票据，云签发失败可原键重试，不创建无限孤立资产。上传端实施大小条件，服务端完成确认仍复核。超时票据不能续写现有完成对象；新尝试使用新 generation 或新 key，不覆盖已绑定文件。配额按用户、用途、时间窗口计算，缓存失败采取受限降级。

**依赖与替身：** 依赖 M00、M01；StoragePort stub 提供签发失败、过期、重试、超额。本地存储必须遵守同样 key 与私有访问约束，不能把开发目录整体暴露为生产静态文件。

**独立验收：** A：U1 申请证件票据后 owner 为 U1，不能指定 U3；超限文件请求返回拒绝且无可用票据；签发超时后同键重试只保留一个资产。B：真实上传完成前业务绑定拒绝，跨用户票据与对象引用拒绝；日志不含签名和临时密钥。C：实际 COS／OSS 验证票据不能写其他 key、列桶或超大小，过期后上传失败，私有对象匿名 GET 被拒绝。

## M02.02 文件验证与绑定

**目标与边界：** 将“上传了字节”变为可信附件，并原子关联业务资源。只做文件真实性、资源限制及绑定所有权；文字／图片是否允许公开由 .04 判定，业务自身决定何时发布。

**工程结构：** 拟建 `MediaCompletionService`、`FileValidationPipeline`、`MediaBindingService`、`domain/MediaAsset`、`MediaRepository`。完成通知仅作触发 → HEAD 及受限读流 → magic bytes／解码／尺寸检查 → 记录验证结果 → `bind` 命令绑定。解码器使用成熟库，限制像素、压缩比、表格单元格和解析时间。

**数据与不变量：** `campus_media_asset` 保存声明／实际 MIME、字节数、hash、generation 和状态；`campus_media_binding` 唯一约束 asset 与绑定目标。客户端不能把他人 asset、自报 hash 或未经验证对象变成有效附件。绑定后对象 key 不可覆盖；默认单一业务归属，复用公开图需显式复制引用策略，私有资料不可跨用途转用。

**接口契约：** `complete(assetId,uploadReceipt)` 返回 `VALIDATING/VALID/REJECTED`；`MediaApi.bind(assetId,owner,ResourceRef,purpose,expectedVersion)` 返回 bindingId/assetVersion，加入调用方事务。错误 `MEDIA_NOT_OWNED/MEDIA_NOT_READY/MEDIA_PURPOSE_MISMATCH/MEDIA_ALREADY_BOUND/FILE_INVALID`；资源授权由服务端 provider 决定。

**执行与失败处理：** 网络检查在事务外读取不可变对象；提交时比对 generation 与版本，防止验证旧对象。绑定事务锁资产并核对状态、owner、检查结果、无删除占用，业务创建与绑定可一起回滚。异步确认重复不重复生成检查任务；验证超时进入可重试状态，失败对象保留有限排障期后清理。

**依赖与替身：** 依赖 .01、M00、M01；StoragePort 提供真实字节夹具，包含扩展名伪造、超大像素、截断 xlsx。检查未通过与业务草稿可共存，但公开发布必须单独要求内容判定通过。

**独立验收：** A：名为 jpg 的其他格式返回 `FILE_INVALID` 且无可绑定状态；U1 绑定 U3 资产拒绝，绑定表零行；两个资源并发绑定同资产只一个成功。B：业务创建后故障回滚，binding 与业务表同步无新行；验证期间 generation 改变，旧结果不使新内容有效；恶意压缩样本被限制且 worker 可继续后续任务。C：真实对象上传／HEAD／读取 hash 一致，完成通知重复不新增绑定，实际存储不允许覆盖已绑定 key。

## M02.03 私有下载与访问审计

**目标与边界：** 在每次签发下载权限时检查用户与业务关系，区分商品公开派生图与证件等私有原件。此项不负责业务成员关系、不授予校园运营全校附件访问，也不承诺已发出的短期签名可即时收回。

**工程结构：** 拟建 `MediaDownloadController`、`DownloadAuthorizationService`、`DownloadPolicy` 与 `AccessAuditRepository`。assetId → 加载绑定与状态 → M01 resource policy → 用途级策略 → 签名或鉴权代理流 → 审计。一般私有文件使用短期链接；需每次访问重验的证件等用途走鉴权代理或同等受控下载通道。

**数据与不变量：** 业务接口仅返回 assetId 和允许的展示元数据；`campus_media_access_log` 记录 actor、resource、action、用途、授权结果、案件理由和 traceId，不保存签名 URL。私有源桶匿名不可读。签名只针对指定版本／对象与短期限；授权撤销阻止新签发，既有链接有效窗口必须被明确记录并按用途控制。

**接口契约：** `MediaApi.authorizeDownload(assetId,actor,purpose,caseRef?)` 返回 `deliveryMode,url/expiresAt` 或受控流入口；`RESOURCE_NOT_ACCESSIBLE` 隐藏非授权资源存在性，`MEDIA_UNAVAILABLE` 用于已获权但对象不可用。治理查看需案件权限及理由，不接受前端传 `isAdmin=true`。

**执行与失败处理：** 授权检查在签发前读取当前关系及资产版本；签发失败不记录虚假的成功下载。必须审计的私有访问若审计无法可靠持久化则拒绝签发。代理流访问重新鉴权，限制响应缓存；签名参数与内容不进入访问日志、分析 SDK 或消息载荷。下载失败不修改原资产归属。

**依赖与替身：** 依赖 .01/.02、M01.06；资源策略 stub 覆盖本人、交易参与者、普通运营、案件授权、已撤销关系。云签名库复用 SDK；图片缩略及前端缓存策略与 M10 联调。

**独立验收：** A：U1 请求 U2 证件返回隐藏资源响应且无签发调用；授权案件操作生成一次审计，缺理由拒绝；审计写入失败时敏感下载不签发。B：订单权限撤销后新链接拒绝，消息外成员不能签附件；私有 API 和事件不含永久 URL。C：匿名请求私有桶失败，实际短期链接到期失败；代理访问撤权即时拒绝，记录普通签名在剩余有效期内仍可能可用这一实测边界。

## M02.04 内容检查与审核结果

**目标与边界：** 为媒体及业务文本提供可追踪的自动检查结果和人工复核入口。格式验证归 .02；最终发布、下架和申诉决定归业务域／M09，本项不能直接把商品改成可售或把活动改成通过。

**工程结构：** 拟建 `ContentInspectionService`、`ContentInspectionPort`、`InspectionCallbackAdapter`、`domain/InspectionResult`。业务提交文本快照／媒体版本 → 建检查任务与 outbox → 调用检查适配器 → 保存版本化判定 → 发结果事件。M09 通过公开命令登记人工判定，业务消费者按自己的待审核版本推进状态。

**数据与不变量：** `campus_media_inspection` 或通用 `campus_content_inspection` 保存 subjectType/id、contentHash、contentVersion、规则版本、渠道请求号、状态与依据码。状态区分 PENDING、PASS、REJECT、REVIEW_REQUIRED、ERROR；渠道不可用不等于 PASS。新内容版本必须重查，旧版本通过不能批准修改后的文本；人工意见与自动结果分别留痕。

**接口契约：** `inspect(subjectRef,contentVersion,contentHash,policy)` 返回 inspectionId/status；`getInspectionStatus` 返回最小结果；`recordManualDecision(id,decision,reason,expectedVersion)` 校验专门权限。错误 `CONTENT_VERSION_CHANGED/INSPECTION_NOT_READY/INSPECTION_CONFLICT`，事件 `media.inspection_completed.v1` 不携带完整敏感材料。

**执行与失败处理：** 创建任务与 outbox 同事务；外部请求使用稳定任务号，回调验证来源并按版本去重。超时保留 ERROR／待重试，达到阈值进人工队列。结果保存与结果事件原子提交；业务订阅离线不丢判定。人工覆盖需明确理由和状态规则，不改写原渠道记录。

**依赖与替身：** 依赖 M00、.02、M01；检查渠道可用受控 stub，但不能把 stub PASS 当成线上内容检查。M09 队列与 M04/M06 发布消费者后续 B 级接入，媒体基础不导入其实现。

**独立验收：** A：同任务重复回调仅一项终态和一个结果事件；旧 contentVersion 的 PASS 不改变新版本状态；渠道超时保持不可公开状态并可重试。B：真实商品改文案后旧通过事件到达，商品仍待审；无权限运营不能人工批准，决定有理由和审计；消费者恢复后得到既有结果。C：真实渠道核验请求与回调认证及错误映射，记录实际能力范围；检查渠道不可用时公开发布仍保持等待或人工审核。

## M02.05 保留清理与证据保全

**目标与边界：** 清理过期孤立对象、减少敏感材料长期留存，同时保证已接受保全的证据不被普通清理删除。保留期限由用途配置并经业务确定，此处不假定统一法定天数；案件结案不自动删除财务或争议材料。

**工程结构：** 拟建 `RetentionPolicyService`、`MediaHoldService`、`MediaCleanupJob`、`StorageDeleteExecutor`。定时扫描候选 → 事务锁资产核对绑定／期限／hold → 标 `DELETE_PENDING` 并创建删除任务 → 事务外删指定 key/generation → 条件记录完成。`hold/releaseHold` 通过同资产锁与删除抢占互斥。

**数据与不变量：** `campus_media_hold` 按 assetId/caseRef 唯一，含理由、创建者、解除权限；资产记录 retentionPolicyVersion、expiresAt、deleteState、objectGeneration。有效 hold 先提交则不得领取删除。已经 `DELETE_PENDING` 的附件不能新绑定，也不能直接返回“保全成功”；只有确认对象仍存在且删除流程已安全终止后才能接受保全。

**接口契约：** `hold(assetId,caseRef,reason)` 返回 holdId/status；`releaseHold(holdId,reason,expectedVersion)` 仅授权方执行；`expire(assetId,policyVersion)` 标记资格而非直接删对象。错误 `EVIDENCE_UNAVAILABLE/DELETE_IN_PROGRESS/HOLD_RELEASE_DENIED`。业务受理证据需检查 hold 成功，不能只异步发送保全通知。

**执行与失败处理：** 删除任务可重试，云删除成功但数据库未确认时以同 key 查证并补记；对象 key 永不复用，旧 worker 不会删新上传内容。租约 fencing 防旧 worker改写任务终态，外部删除竞态仍由不可变 key 和状态不复活约束处理。云端对象缺失进入异常记录，不伪造仍保全；解除最后一项 hold 后重新计算保留资格。

**依赖与替身：** 依赖 M00.05、.01/.02、M01；M09 通过 hold API 引用证据。StoragePort stub 支持删除成功超时、对象缺失和拒绝，Clock 可推进验证保留期。

**独立验收：** A：hold 先提交后清理扫描，对象不被调度删除；删除先抢占后申请 hold 返回明确失败，案件不能记保全成功；云删除成功后进程退出，重试终态为 DELETED 且无新对象误删。B：真实案件 hold 与资产事务配合，解除一项但仍有其他 hold 时不删；未绑定上传到期被清理，正在正式课表使用的附件按其用途策略处理。C：真实桶验证对象删除与访问失效，预发演练云端拒删／缺失均有可查询异常和脱敏审计。
