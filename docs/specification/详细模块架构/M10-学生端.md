# M10 学生端详细模块架构

版本：v1.1，2026-09-17。本文为待实施设计；接口、目录和组件名为拟定契约，验收均未执行。遵循《00-工程约定与独立验收规范》，采用 uni-app Vue3、unibest 和 Wot UI，不另建基础控件体系。

## 总览、内部依赖与共享边界

M10.01 提供视觉与交互基础，M10.02 管理导航和浏览上下文，M10.03 管理 API、会话和恢复；M10.04–M10.09 分别拥有账号、二手、跑腿、活动、课表、消息页面。依赖方向为业务页面 → 基础能力，业务页面之间通过路由参数、公开 API 和只读上下文联系，不互改 store。

计划目录根为 `apps/student/src/`。`components/base`、`styles` 归 .01；`router`、`stores/context`、分包配置归 .02；`services/http`、`services/session`、API 生成接入归 .03；各 `features/*` 与所属页面归对应业务子模块。生成类型来源 `contracts/openapi`，各后端领域拥有业务契约，前端不得自行扩充服务器状态。

主包只放四标签入口、登录、选择学校及必要共享组件；复杂详情、发布、导入、订单页面位于业务分包。服务端拥有权限、金额、名额、有效预约和资金事实；前端只表达事实与用户意图。持久草稿按账号和校区隔离，排除证件、取件码及会话令牌；临时媒体路径在提交或退出后清理。样式采用人工视觉验收，状态恢复与跨账号隔离须有可重复用例。验收引用 S1/S2、U1/U3 等共享样本，A 级用例使用同版本契约 stub。

## M10.01 主题与基础组件

**目标与边界：** 建立手机端一致的阅读、表单和状态体验，拥有主题 token、基础布局和通用反馈；不在按钮组件中判断接单或退款资格。沿用 Wot UI 的输入、弹窗和选择器，仅封装业务需要的统一外观。

**工程结构：** `styles/tokens.scss` 定义颜色、字号和间距；`components/base/{PageShell,EmptyState,ErrorState,SubmitBar,MoneyText}` 消费 token；页面将状态和事件传给组件，组件向外发出点击、重试、取消事件。禁止组件直接读取业务 store 或访问接口。

**数据与不变量：** 正文约 16px，辅助 13–14px，标题 18–20px；白灰背景、绿色强调，关键触控区至少 44px。MoneyText 输入整数分与币种，ID 不做数值转换。加载、空、失败和正常内容互斥；颜色之外还用文字说明状态。

**接口契约：** 设计 `PageState=loading|empty|error|ready`；`ErrorState` 接收可展示信息、traceId 和 retryable；`SubmitBar` 接收 busy/disabled/label 并发出 submit。缺少金额显示“待确认”，不得显示成零；未知状态保留可理解的兜底文案。

**执行与失败处理：** 提交条考虑底部安全区与键盘，长文自然换行，弹窗关闭恢复焦点。局部网络失败只替换对应内容区，不清空整页；重试按钮由页面处理。图标失败使用本地占位，文字仍可操作。

**依赖与替身：** 依赖 M00 固定构建版本，业务依赖为纯 props 样例。组件展示页提供长校名、长价格、空白和错误样例，不引入真实账号。

**独立验收：** A：依次加载四种状态→不存在空状态与数据重叠；输入长标题和缺失金额→换行且不伪造零元；连续点击 busy 按钮→不发第二次 submit。B：接入一个真实发布表单→字段错误紧贴字段、重试保留内容。C：320/390/430px 对应布局及至少一台微信真机打开键盘、放大系统字体→提交条可达、无横向溢出，并保存截图；这不代表所有机型已覆盖。

## M10.02 导航学校上下文与分包

**目标与边界：** 固定“校园／课表／消息／我”导航与校园内三业务切换，拥有浏览学校、校区和功能可用性；切换浏览范围不增加认证权限，不自动迁移私人课表所属学期。

**工程结构：** `router/` 校验深链和重定向；`stores/context` 保存服务端上下文及 generation；主包标签页跳转 `pages-market/` 等业务分包。数据流为启动/切校 → context API → 范围校验 → 清理范围缓存 → 展示入口；旧请求携带 generation，返回时检查后再应用。

**数据与不变量：** schoolId/campusId 必须匹配；浏览上下文和成员资格分别存储。列表缓存键含账号、校区、筛选条件，禁止跨校串页。功能关闭限制新增行为，历史订单入口仍在；校园页三列表分别保留合理滚动位置。

**接口契约：** 设计 `GET /app-api/campus/v1/context` 返回成员范围、浏览范围和功能配置版本；`switchCampus(campusId)` 返回已确认上下文，失败为 CAMPUS_DISABLED 或 SCOPE_DENIED。深链只携带资源 ID 和可验证范围，不能携带可信权限或 token。

**执行与失败处理：** 首次缺少校区进入选择页；切校中禁止新发布，已有草稿提示保留原校区。无权深链显示拒绝并给安全返回入口；配置加载失败使用明确的离线提示，敏感写操作不据过期配置放行。分包加载失败可重试且不丢会话。

**依赖与替身：** 依赖 .01/.03、M01 上下文、M09 功能配置；stub 返回双学校、停用校区、关闭新跑腿与延迟响应。分包体积验证使用实际构建产物。

**独立验收：** A：S1 请求未返时切 S2→晚到 S1 响应不覆盖；关闭跑腿新增→入口受限但旧订单可打开；未授权深链→不显示私有内容。B：真实后端切校并发布→服务端校区与页面一致、伪造范围被拒。C：微信真机从分享卡片冷启动和下载分包→回到正确页面；提交构建包大小报告及超限处理记录，不能用 H5 体积替代。

## M10.03 请求会话与错误恢复

**目标与边界：** 统一请求、学生会话、错误转换、幂等键和网络恢复；不复制后台登录机制，不让页面直接操作 token，不把超时解释为业务失败。

**工程结构：** `services/http/client` 包装 uni.request；`services/session` 单飞刷新会话；`services/commands` 保存未决命令 ID；`api/generated` 接入生成类型。调用流为 composable → API client → 会话与错误拦截 → 服务端，业务错误回到页面做明确决策。

**数据与不变量：** 所有 ID 为字符串，金额整数分。幂等键绑定一次用户意图和请求摘要，重试复用原键，用户修改内容产生新意图。会话缓存按账号隔离；日志只留路由、业务错误、耗时和 traceId，不留凭据或完整请求体。

**接口契约：** 设计 `request<T>` 输出统一响应；错误区分 AUTH_EXPIRED、FORBIDDEN、VERSION_CONFLICT、RATE_LIMITED、NETWORK_UNKNOWN。`executeCommand` 接收幂等键、expectedVersion 与查询原结果的方法；无安全查询契约时明确返回待确认，不私自重发写请求。

**执行与失败处理：** 同时出现过期只刷新一次；刷新失败清会话并导航登录。GET 可有界重试；写请求只在幂等和恢复契约允许时重试。重新登录若变更账号，丢弃旧请求队列；身份未变也需确认未决敏感操作，避免意外提交。网络恢复只刷新可见页面。

**依赖与替身：** 依赖 M00 响应规范与各领域查询契约。注入 `Transport`、`SessionProvider`、Clock 和随机数源；stub 可模拟提交成功后断网、401 并发、429 与乱序响应。

**独立验收：** A：十个请求同时401→刷新一次；服务器提交成功后超时→查询原结果且不创建第二笔；U1请求挂起后登录U3→U1结果不进入U3页面。B：真实幂等后端同键同体/异体→分别返回原单/冲突，并验证界面提示。C：微信真机断网、恢复、切后台→表单仍在，未决命令可查询，脱敏日志可用 traceId 关联服务端。

## M10.04 账号认证与个人中心

**目标与边界：** 提供登录、学校认证、跑腿资格状态和个人功能入口；微信登录、手机号、学校认证分别展示。认证状态仅从 M01 获取，不由本地填写的学校名推断。

**工程结构：** `features/account/{api,composables,views}` 与 `pages/me`；认证表单调用媒体上传适配，再提交 M01；个人订单入口只跳转所属领域列表。`useAccountProfile` 消费会话变化并清空上一账号数据。

**数据与不变量：** 展示昵称、成员关系、认证来源摘要及到期时间，不长期缓存证明材料。上传引用含用途与 assetId，归属由服务端验证。待审核、驳回、过期、通过明确区分；个人中心不聚合展示未经核实的收入数字。

**接口契约：** 设计微信临时 code 登录适配，以及 `GET .../account/profile`、`POST .../verifications`；认证输入 schoolId、channel、assetIds、幂等键，输出 verificationId/status/version；错误含 MEDIA_NOT_READY、VERIFICATION_PENDING、SCOPE_DENIED。手机号流程按固定上游接口接入，不另造用户主表。

**执行与失败处理：** 登录取消返回原页，可继续允许的公开浏览。材料上传失败保留非敏感表单并显示失败文件；审核中可查询进度，驳回展示可披露理由。资格过期即时刷新提示，旧履约订单继续从个人订单入口访问。退出清理私有缓存及连接。

**依赖与替身：** 依赖 .01–.03、M01 账号认证、M02 私有上传；微信临时 code 由注入的平台登录适配提供，A 测试不假称完成微信认证。

**独立验收：** A：取消登录→返回原浏览页；上传两件一件失败→不提交不完整认证；资格从通过变过期→按钮提示更新且旧订单入口保留。B：真实上传与认证队列→U1只能绑定本人材料，管理员决定后学生状态一致；退出再登录U3→不见U1材料。C：微信真机授权取消、登录成功与文件选择→交互可恢复、无证件图进入公开URL，记录实际登录渠道。

## M10.05 二手页面闭环

**目标与边界：** 覆盖出售/求购、搜索、发布、预约、自提确认及举报；首次交易线下付款，界面不显示虚构的已支付状态。预约和成交规则由 M04 决定。

**工程结构：** `features/market/{api,stores,composables}`、`pages-market/{detail,publish,reservation}`；列表筛选驱动查询，详情使用资源 ID 重新获取状态；发布复用上传，私聊跳转 .09 的会话入口。独立 store 只缓存本领域视图。

**数据与不变量：** 草稿绑定账号、校区和类型；求购不强套出售预约。页面区分 AVAILABLE、RESERVED、SOLD 和下架；双方确认与“其他渠道售出”使用不同文案。公开列表无私下约定和联系方式，金额标明卖家报价或用户申报。

**接口契约：** 设计列表、发布、详情 API；预约沿用 `POST .../market/listings/{id}/reservations`，输入 expectedVersion、幂等键，输出预约状态/有效期。确认输入 reservationId 与版本；错误含 ALREADY_RESERVED、RESERVATION_EXPIRED、LISTING_UNAVAILABLE，返回可披露的最新状态。

**执行与失败处理：** 图片未处理完不得发布；提交超时查询原发布结果。预约冲突刷新详情、保留浏览位置；预约倒计时仅辅助显示，到期操作由服务端判断。对方下架后历史约定仍按授权可查，当前新增预约关闭。举报成功显示案件编号。上传中离页先提示，取消后保留已填文本而不绑定未完成附件。

**依赖与替身：** 依赖 .01–.03、M02/M04/M07/M09；stub 提供并发预约失败、已下架卡片、单方确认与他渠售出样本；真实预约锁由M04验收。

**独立验收：** A：发布返回超时后查到原帖→仅一张成功页；预约冲突→不显示预约成功；卖家标他渠售出→不展示双方成交。B：U1发布、U2私聊预约双方确认→真实列表/详情/统计来源一致；第三人不能读取约定。C：微信真机拍照、弱网上传、搜索回退和私聊跳转→草稿不丢、长描述不遮提交，完成一条可回放交接流程。

## M10.06 跑腿页面闭环

**目标与边界：** 覆盖下单者与跑腿员的报价、付款、接单、履约、取消、争议及到账查看；前端不确认支付结果，不将完成订单等同到账。

**工程结构：** `features/errand` 拆 `useCreateOrder/useFulfillment/useRunnerOrders`；`pages-errand` 包含表单、详情和证据页；`services/platform/payment` 封装平台支付调用。状态流为服务端报价 → 建单 → 支付参数 → 平台调用 → 查询支付/订单 → 刷新视图。

**数据与不变量：** 价格和取消规则显示服务端快照；履约、支付、结算状态分栏展示。取件码仅合法接单者可见，不进入列表、日志或永久草稿。新跑腿关闭后已有订单保留送达、争议和退款进度入口。

**接口契约：** 设计 quote/create/detail/accept/deliver/complete/cancel/dispute；敏感命令带幂等键与版本。prepay 返回平台参数，query 返回真实付款状态。错误含 QUOTE_EXPIRED、ALREADY_ACCEPTED、RUNNER_INELIGIBLE、STATE_CONFLICT；资金 UNKNOWN 显示待核对而非失败。

**执行与失败处理：** 调起支付成功仅开始查单；取消/超时继续查原单，不重新建单扣款。接单失败移除失效按钮并刷新。证据上传失败不确认送达；争议提交后显示服务端返回的冻结/在途说明，不承诺撤回已执行款项。模拟环境显著标识。平台支付能力不可用时展示原因，保留原订单供后续查询。

**依赖与替身：** 依赖 .01–.03、M01/M02/M05/M08/M09；PaymentAdapter提供取消、未知、成功但回调延迟替身，履约 API stub 独立于财务实现。生产禁止模拟渠道由 M11 校验。

**独立验收：** A：SDK成功但查单待确认→订单不开放接单；抢单失败→无取件码；已完成/打款处理中→清楚显示未到账。B：真实业务与模拟网关跑创建、取消后晚付款、争议三路径→界面对应退款补偿/冻结事实。C：获批微信真机小额收款、退款和跑腿员收款确认→分别核对渠道证据；条件缺失记录C待验，不以模拟画面代替。

## M10.07 活动页面闭环

**目标与边界：** 覆盖免费活动发布、审核状态、报名、候补、退出及签到；主办者工作区仅暴露获授权名单。容量和候补顺序由 M06 维护。

**工程结构：** `features/activity/{api,stores,composables}`、`pages-activity/{detail,publish,registration,checkin}`；活动详情和本人报名分别查询，再合成视图；扫码能力由平台适配提供，解码结果交服务端验证。

**数据与不变量：** 活动状态与用户报名状态分离；候补不是已报名，展示序号为服务端快照。人数不得由前端累加推断；签到码是短期凭证，不作为公开分享图。首期无付费入口，禁止依据未知 price 字段自行开放付款。

**接口契约：** 设计发布/详情 API、`POST .../activities/{id}/registrations`、退出及签到命令；输入资源ID、版本、幂等键，签到附短期凭证。输出 registrationId、status、waitlistPosition、期限；错误含 CAPACITY_FULL、REGISTRATION_CLOSED、EVENT_CANCELLED、CHECKIN_TOKEN_EXPIRED。

**执行与失败处理：** 详情人数过期不阻止请求，报名响应决定成功或候补。弱网重复报名查询同一报名记录；整场取消刷新通知和详情。候补提升消息只触发重读本人状态。签到过期提供重新获取入口；未授权组织者不展示受限报名资料。名单分页按活动版本刷新，退出者不因旧页面缓存继续呈现为有效报名。

**依赖与替身：** 依赖 .01–.03、M01/M02/M06/M07；stub 包含剩余1名额变0、候补提升、活动取消与过期码；测试不靠前端锁证明容量正确。

**独立验收：** A：展示剩1后报名返回候补→页面明确候补；旧通知点击已取消活动→无报名按钮；过期扫码→不显示签到成功。B：真实容量满额、退出、候补提升→两用户视图及服务端占位一致；非主办账号访问名单被拒。C：两台微信真机扫码及分享冷启动→正确校区和活动、重复签到显示原结果、取消活动仍能查看历史报名。

## M10.08 课表页面与导入纠错

**目标与边界：** 提供今日/周课表、手工编辑、文件/截图导入、低置信纠错、差异确认和撤销；识别结果展示为草稿，页面不自行推断未给出的周次与学期锚点。

**工程结构：** `features/timetable` 拆 `useWeekView/useImportDraft/useTermSettings`；`components/TimetableGrid` 只渲染；`pages-timetable/{import,review,course,term}` 调用 M03。上传 → 异步任务轮询 → 草稿编辑 → 差异预览 → 确认 → 重读正式周视图。

**数据与不变量：** 学期含时区、首周周一与节次表，课程多条安排保留不同周集合/地点。正式版本与草稿版本分开，冲突课程不可被覆盖隐藏。默认不持久缓存私人课程内容，草稿恢复通过本人任务ID查询，未提交修改离页前提示。

**接口契约：** 设计 weekView、term、imports/status/draft/diff/confirm/undo；确认输入 draftVersion、baseRevision、幂等键和处理模式，与 M03.07 契约一致，输出新版本。错误含 INVALID_WEEK_RANGE、LOW_CONFIDENCE_UNRESOLVED、VERSION_CONFLICT、UNDO_CONFLICT；原图授权过期可申请新地址。

**执行与失败处理：** 轮询退避并在后台暂停，回前台查任务；OCR不可用保留重试和文件/手动入口。低置信字段逐项标明，不用全页警告掩盖具体问题。确认超时查原提交；期间课表被修改则重新预览，撤销冲突不覆盖后续编辑。

**依赖与替身：** 依赖 .01–.03、M02/M03；固定Clock和脱敏样本覆盖单双周、非连续周及日期调课。stub可测纠错流程，但识别准确率必须使用真实OCR样本。

**独立验收：** A：单双周和同课不同教室→周视图正确分组；确认冲突→保留草稿要求重预览；OCR失败→原正式课表不变。B：真实解析上传至确认再撤销→版本和课程数量对应预期；低置信未解决不能提交。C：微信真机选择课表截图、编辑周次并后台返回→任务可续；网格横纵滚动与键盘可用，另附实际样本字段准确率，不能宣称全国适配。

## M10.09 消息收件箱与实时同步

**目标与边界：** 提供私聊、业务通知、未读数和实时恢复；WSS只提高及时性，完整历史和授权以 M07 为准。消息卡片不直接修改其他领域订单状态。

**工程结构：** `features/message/{api,stores,composables}`；`services/realtime` 管理原生 WSS；`pages-message` 渲染会话/聊天；`BusinessCard` 仅按业务类型与ID导航。发送通过持久化API，推送与HTTP补拉共同进入同一 seq 合并器。

**数据与不变量：** 用 conversationId+seq 去重，发送用稳定 clientMessageId；收到ACK才显示已发送。分别维护最后连续同步 seq、已应用 changeSeq 和最大已读 seq，不能把最大收到 seq 当连续游标跳过缺口。私聊内容只在内存，退出/换账号清空；未决发送 ID 不包含消息正文。进程重启后没有正文缓存时从授权历史重新加载，不仅恢复一个裸游标而跳过尚未展示内容。

**接口契约：** 设计会话列表、send、afterSeq 新消息补拉、afterChangeSeq 旧消息变更补拉、read 与短期连接票据 API；send 输出 messageId/seq，WSS 事件含会话 ID、seq/changeSeq 与类型。错误含 NOT_MEMBER、BLOCKED、TICKET_EXPIRED、MESSAGE_REJECTED、HISTORY_RESYNC_REQUIRED；撤回／审核删除保留原 seq 占位。

**执行与失败处理：** 重连先取新票据，分别补拉新消息与历史变更，应用成功后才推进各自连续游标；收到缺口触发补拉。游标过旧时按服务端授权起点重建历史，不能继续显示已撤回缓存。发送超时用原 clientMessageId 重试；拒绝明确标识。后台断连正常，回前台补齐；旧业务卡片点击重新查询资源。订阅消息拒绝不影响站内通知。补拉失败保留已显示记录并标明未同步；会话授权被撤销则清除正文。

**依赖与替身：** 依赖 .01–.03、M07和业务上下文 API；可控WSS替身发送乱序、重复、缺口和过期票据。禁止引入Socket.IO客户端连接原生WSS。

**独立验收：** A：先收 seq3 后 seq2→补拉 seq1 不丢消息；ACK 丢失重发→仅一条显示；换账号时旧连接回包→丢弃。B：已读取的 seq2 在离线时被撤回，重连 changes 补拉后旧气泡变占位；多端已读按服务端规则一致，旧游标要求重同步，非成员请求被拒。C：微信真机切后台、断网、恢复及拒绝订阅授权→新消息和旧消息变化均补齐；杀进程重启后历史仍可加载，留脱敏日志。
