## 2. 开发推进顺序

顺序表示可工作的工程层次，不要求等整批全部完成后才启动下一批。相邻契约冻结后可以用替身并行实施；跨模块事务必须补足真实集成验收。

| 批次 | 首先交付 | 可以接着推进 | 完成信号 |
|---|---|---|---|
| W0 固定底座与契约 | M00.01–.03；统一 DTO、错误和迁移 | M10.01–.03、M11.01/.05 的应用骨架 | 固定版本可构建，接口与环境可重复 |
| W1 公共运行能力 | M00.04–.06；M01.01/.02/.04/.06；M02.01–.03 | 认证与资格、文件检查／保留、消息基础 | 身份、范围、上传、事务和恢复有 A 级证据 |
| W2 业务聚合与资金骨架 | M03.01/.02；M04.01；M06.01/.02；M05.01/.02；M08.05 guard 基础与 M08.07 | M08.01–.04、M07.01–.04、M09.01/.05 | 关键聚合与资金同事务入口建立 |
| W3 完整领域流程 | 课表其余项、二手预约确认、活动候补签到取消、跑腿接单履约争议 | 结算分配／打款／对账、M09.02–.04/.06、业务通知 | 并发、权限、失败恢复和跨域 B 级证据齐全 |
| W4 两端集成与真实依赖 | M10.04–.09、M11.02–.04/.06–.08 | 按已具备条件完成微信真机、真实存储和受控小额资金 | 必要 C 级证据、恢复演练与单校试点条件满足 |

前端可提前按契约制作页面；W4 是真实集成收口。截图识别依赖真实脱敏样本，付费试点依赖实际收款与跑腿员收款权限；这些条件未具备时记录待验证，不阻塞其他可独立工作的模块。

## 3. 共享边界必须一起验证

| 交接点 | 涉及模块 | 必须保持的规则 |
|---|---|---|
| 学校与资源授权 | M01、M02、各业务、M10/M11 | 浏览校区不授予身份；列表、详情、导出、附件、WSS 同样执行范围 |
| 接单与资格停用 | M01.05、M05.03 | 资格→订单→负载锁序；停用不反向锁任务，重复完成只释放一次额度 |
| 争议与资金冻结 | M09.03、M05.05、M08.05 | 案件、履约关联与冻结同事务；按原因逐项解除，不能清掉其他冻结 |
| 支付事实与台账 | M08.02–.07、M05.02 | 可信状态、分录和 outbox 同事务；未知渠道结果复用原单查证 |
| 报名与候补 | M06.01–.03/.05 | 单一容量入口，候补经同一事务占位，取消期间不得新增报名 |
| 导入与课程编辑 | M03.02–.07、M10.08 | 候选不直接落正式课表；确认／撤销检查 revision，不覆盖后续手改 |
| 媒体与争议证据 | M02.02/.03/.05、M09.03 | 所有权、资源授权和保全成立后才承诺可用；删除中不虚称保全成功 |
| 消息与客户端游标 | M07.02–.04、M10.09 | 数据库持久化、客户端按连续 seq 补齐，乱序推送不能推进越过缺口 |
| 发布与资金恢复 | M08.08、M11.05–.08 | 恢复旧备份先暂停资金执行并补账；旧客户端契约持续兼容 |

这些是集成规则，不能通过把函数再拆小来消除。共享聚合类只维护一份；独立验收不等于独立部署。

## 5. 如何使用这套文档

1. 选一个子模块，读取公共规范、该模块共享边界和对应七项详细设计。
2. 固定契约、依赖替身与代码拥有范围，再开始实现；共享类变更先协调。
3. 按指定输入、故障和并发场景执行 A 级验收，交付代码及可重复证据。
4. 接通相邻真实模块完成 B 级验收；有第三方条件的再补 C 级证据。
5. 更新任务状态，但不要把“文档结构检查通过”写成“产品测试通过”。
