# 给后端模型的联调说明

## 接手方式

前端在 `apps/student`，18 个学生端页面已实现。请先读现有产品架构，再读本文件和 `src/types.ts`；保留现有后端技术选型。这里是前端候选契约，接口路径与 DTO 可以由适配层转换。不要因为前端演示字段就重建后端领域模型。

所有页面只调用 `src/services/api.ts`。真实传输在 `src/services/transport.ts`，默认演示在 `src/data/demo.ts` 和 `src/state.ts`。真实模式尚未完成端到端联调。

## 当前传输约定

- 基址环境变量 `VITE_API_BASE_URL`，示例 `/app-api/campus/v1`。
- 响应包装 `{ code: 0, data: T, message?: string, traceId?: string }`，`msg` 也兼容。HTTP 非 2xx 或 code 非 0 均失败。空写入可返回 `data: null`。
- 登录后 `Authorization: Bearer <accessToken>`；token 目前只保留内存，无刷新 token 机制。H5 暂无真实微信网页登录入口，`uni.login(provider:weixin)` 需要小程序环境。
- 写命令携带 `Idempotency-Key`，同一未确认请求重试复用键。前端不自动重试支付。网络错误叫 `NETWORK_UNKNOWN`，不能据此认定服务端没有完成。
- market/errands/activities 命令补入 `campusId`，有本地记录时补入 `expectedVersion`。后端必须核验账号权限、校区与版本并在事务内执行，前端判断不能作为安全边界。
- 金额统一整数分；演示跑腿固定服务费 80 分不代表商业定价。真实费用必须后端报价，支付结果仅以服务端查询/渠道回调为准。
- 当前前端是评审版本：加载第一页最多 50 条后在内存筛选；分页、详情独立读取、按账号的完整历史列表和游标消息需要下一轮联调完善，不能把第一页当完整记录。

## 已预留的请求

以下均相对基址。ID 取自服务器，不应直接采用演示的 book / parcel 等。

| 方法与路径 | 输入 | data / 页面用途 |
|---|---|---|
| GET `/schools` | `keyword?`、`cursor?` | 公开学校/校区目录源：`{items:[{schoolId,name,timezone,status,configVersion,campuses:[{campusId,schoolId,name,timezone,status,configVersion}]}],nextCursor}`；前端以此组装校区选择器，不要求 `/context` 重复目录 |
| GET `/context` | 无 | 当前选择与会话状态：`{loggedIn,browseMode,school?,campus?}`；可返回兼容扁平结构；adapter 与 `/schools` 合并成 `{campuses, campusId, user}`；访客/无偏好时 `school/campus` 可为空 |
| PUT `/context` | `{schoolId,campusId}` | 只保存当前浏览偏好，随后重载上下文；校区归属由后端校验。旧候选 `POST /context/campus` 不再是 canonical 路径 |
| POST `/auth/wechat/login` | `{code,clientContext?}` | `{accessToken,expiresAt?,userId?,profileCompletion?}`；前端只依赖 `accessToken`。旧候选 `POST /auth/login` 不再是 canonical 路径 |
| POST `/auth/logout` | 无 | 失效会话；前端先清本地私密状态 |
| POST `/verifications` | `{name, studentId}` | 提交后状态 PENDING，不能直接认作 VERIFIED |
| GET `/market/listings?campusId=…&limit=50` | 查询参数 | `{items: Product[]}` |
| POST `/market/listings` | 标题/描述/价格/分类/成色/瑕疵/地点/类型/图片引用 | `Product`；真实图片上传未接，发布页暂禁真实提交 |
| POST `/market/listings/:id/favorite` | `{campusId,expectedVersion}` | 收藏切换；生产建议改为设置明确 favorite:true/false |
| POST `/market/listings/:id/reservations` | 同上 | 预约；后端保证唯一有效预约 |
| POST `/market/listings/:id/reservation/cancel` | 同上 | 仅预约者取消，状态冲突返回明确错误 |
| POST `/market/listings/:id/confirm` | 同上 | 仅当前买家确认；应补充卖家确认接口与双方状态 |
| POST `/market/listings/:id/conversation` | 同上 | 当前 adapter 预期字符串 conversationId，若后端返对象在此转换 |
| GET `/errands/available?campusId=…&limit=50` | 查询参数 | `{items: Errand[]}`；不包含私密取件凭证 |
| POST `/errands` | title/category/pickup/destination/rewardFen/deadline/description/weight/campusId | `Errand`，初始 WAITING_PAYMENT |
| POST `/errands/:id/accept` | `{campusId,expectedVersion}` | 原子接单，认证、并发上限、发布者不可接自己订单 |
| POST `/errands/:id/advance` | 同上 | 当前 adapter 的通用履约动作；建议后端按取件/送达/收件确认拆端点，适配层映射 |
| POST `/errands/:id/cancel` | 同上 | 返回权威订单/支付状态，不凭按钮改成退款成功 |
| GET `/activities?campusId=…&limit=50` | 查询参数 | `{items: Activity[]}` |
| POST `/activities` | title/category/date/time/location/description/capacity/cover/campusId | `Activity`，PENDING_REVIEW |
| POST `/activities/:id/registrations` | `{campusId,expectedVersion}` | 事务分配正式名额或候补 |
| POST `/activities/:id/registration/cancel` | 同上 | 退出及候补递补应由后端完成 |
| POST `/activities/:id/checkin` | 当前无凭证 | 真实 UI 禁用；接签到凭证后再开放，不能仅靠 activityId |
| GET `/me/workspace` | 登录身份 | `{courses, conversations, notices, favorites}`；当前聚合过渡接口 |
| POST `/timetable/courses/save` | `Partial<Course>`，修改带 id | 创建/更新；建议后端分 POST / PUT 由适配层转换 |
| POST `/timetable/courses/:id/delete` | `{}` | 删除本人课程 |
| POST `/timetable/imports/confirm` | `{courses: Course[]}` | 原子追加；将来需 draftId/version/确认后的字段，当前真实示例导入已禁用 |
| POST `/conversations/:id/messages` | `{text}` | 保存本人消息；需补 clientMessageId、seq 和游标同步 |
| POST `/conversations/:id/read` | `{}` | 应改为 highestReadSeq，避免把晚到消息误标已读 |
| POST `/notices/read` | `{}` | 当前全部已读；正式接口建议带 noticeIds 或最高游标 |

`/errands/:id/demo-pay` 仅演示分支在本地运行，不发送网络请求，不应实现成真实后端支付捷径。真实支付、报价、退款、订单查询端点需按原支付架构接入。

## DTO 与状态的映射重点

准确字段由 `src/types.ts` 定义。示例时间如“9 月 18 日 · 周五”“刚刚”为展示字符串，生产应传 ISO 时间、学校时区和日期，适配层格式化。

- `Product`：SELL/WANTED；AVAILABLE/RESERVED/SOLD/PENDING_REVIEW；`buyerConfirmed` 目前只演示买家单侧确认。应补 reservationId、双方确认、操作权限，而不是通过前端 Map 判断真实授权。
- `Errand`：订单状态与 `paymentStatus`、`payoutStatus` 独立。收件确认仅进入 payout PENDING，不能显示已到账；取消已支付订单仅进入 REFUND_PENDING。
- `Activity`：活动状态 OPEN/CANCELLED/PENDING_REVIEW 与当前用户参加状态 NONE/CONFIRMED/WAITLISTED/CHECKED_IN 分开，数量及候补位序由后端决定。
- `Course`：day 1–7；start 1–12；duration 1–4，不能超出第12节；weeks 是1–20整数数组；color来自固定柔和色板。学校作息与学期开始日未来由 context 下发。
- `Conversation`：关联 contextType/contextId，消息 seq 单调递增。演示只保存内存，不伪造对方回复。真实尚未接 WSS、断线补拉、分页、客户端消息去重及撤回事件。
- `User`：loggedIn 是前端会话展示，verification 独立，runner 必须来自服务端授权，不能由学生在设置里自行修改。

### M01.02 前端联调边界

- `/schools` 是公开目录的唯一来源；`/context` 只描述当前学校/校区选择和会话状态。前端刷新允许并行读取两者，并在 adapter 中合并，不要求后端把目录塞回 context。
- canonical ID 为 `schoolId`/`campusId`，前端暂兼容旧候选 `id`；每个 `Campus` 都保留所属 `schoolId`，切换时只向 `PUT /context` 发送该权威归属。
- 状态 `ENABLED`/`ACTIVE` 映射为可用，`DISABLED`/`INACTIVE` 映射为不可用。context 没有选择时，前端最多将目录中第一个可用校区作为公开浏览默认值，不会自动 PUT，也不会因此创建身份。
- 仅当服务端给出 `user` 对象中的字段时，前端才展示用户 ID、认证状态或跑腿权限；顶层 `loggedIn` 会被识别，但不会伪造用户身份、verification 或 runner 权限。
- 本节记录的是适配层契约和验收边界，不宣称已完成真实后端进程联调；真实环境仍需后端提供可访问地址、OpenAPI/示例响应和测试账号后再验收端到端链路。

## 必须补的真实数据读取

当前只有公开列表和私有 workspace；真实模式个人订单、本人待审核发布、已结束活动，以及链接直达但不在第一页的详情可能查不到。请新增或映射：

1. 各业务 `GET /:id`，按是否本人/参与者裁剪私密字段。
2. 我的发布、我的订单（发单与接单）、我的活动、收藏列表独立分页。
3. 聊天按 cursor/seq 读取与重连补拉；通知分页。
4. 文件上传签名、大小和类型校验、处理任务、OCR/表格识别 draft、人工纠错确认。
5. 服务端报价与支付订单查询、超时未知态查询恢复、退款/结算只读状态。

## 建议联调顺序

先 context/登录/公开读取，随后二手详情/收藏/发布/会话，再课表 CRUD 与导入，最后跑腿报价支付与活动并发名额。每一批接口给出 OpenAPI、示例响应、错误码、测试账号和可访问地址，前端在适配层实现映射。

先建立后端权威状态，再开放实际资金按钮。新增真实接口前无需改整个 UI；请保留演示模式便于产品评审。

## 可直接复制给后端模型

> 前端已完成可交互学生端，工程在 campus-frontend/apps/student。请阅读 docs/后端联调说明.md、src/types.ts 与 src/services/api.ts，并结合你已有后端架构给出真实 OpenAPI 和字段映射。本文为候选契约，请保留后端领域模型，在适配层处理差异。先交付 context、登录和校园列表/详情，再按文档顺序联调。重点保证校区隔离、权限、幂等、版本并发、支付/履约/结算分离，不要把演示支付端点或示例 OCR 当作真实能力。
